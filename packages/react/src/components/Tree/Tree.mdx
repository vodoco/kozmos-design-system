# Tree

Tree presents hierarchical data with disclosure, selection, keyboard navigation,
optional counts, metadata, and safe nested row actions. Use `TreeParentItemRow`
and `TreeChildItemRow` when product screens need to compose custom trees from
reusable parent and terminal row primitives.

`Tree` supports both data-driven rendering and a composed shell mode. Use `data`
when the tree owns expansion, roving focus, and selection. Use children when a
screen needs to hand-compose parent and child row primitives inside a semantic
tree container.

## Composing a tree

Every row is a treeitem, whether `Tree` draws it from `data` or you compose it.
A composed tree has three parts:

- **The container:** `Tree` with children is the `role="tree"`, named by
  `ariaLabel`.
- **The rows:** `TreeParentItemRow` for a row with children, `TreeChildItemRow`
  for one without. Each row carries its own level and state from the props it
  already takes.
- **The groups:** an expanded parent's children go in a `<div role="group">`
  right after its row, at `depth` one more.

| Row prop   | What it gives the row                                    |
| ---------- | -------------------------------------------------------- |
| `depth`    | The indent, and `aria-level`, one more (0 is level 1)    |
| `expanded` | `aria-expanded`, on `TreeParentItemRow` only             |
| `selected` | `aria-selected`, and the selected fill                   |
| `disabled` | `aria-disabled`, and the dimmed row                      |

```tsx
<Tree ariaLabel="Map content">
  <TreeParentItemRow name="Outdoor map content" count={23} expanded />
  <div role="group">
    <TreeParentItemRow name="Terminal C" depth={1} expanded />
    <div role="group">
      <TreeChildItemRow name="Burger King" depth={2} selected />
      <TreeChildItemRow name="McDonald's" depth={2} />
    </div>
    <TreeParentItemRow name="Terminal D" depth={1} />
  </div>
  <TreeChildItemRow name="Archived content" disabled />
</Tree>
```

Leave out `role` and the `aria-*` states: the row sets them. A `role` or
`aria-*` of your own still wins, and with a role other than `treeitem` (`"none"`
inside a treeitem of your own) the row adds no tree state. Keep the row's
state in your own state, so `expanded` and `selected` change as the screen
does.

A composed tree has no keyboard of its own: `Tree` moves focus with the arrow
keys, Home and End only through `data`. Use `data`, with its `icon`, `count`,
`meta` and `actions` slots, when the tree needs the keyboard.

A composed row takes the same `icon`, `count`, `meta` and `actions` as a row
from `data`:

## Divided

`divided` draws a 1px stroke under every row in the border role, and sets an open parent row on a
surface of its own, background 50 (GAP-201): a tree of records, as Pointr Cloud's Map Content tree
draws its buildings and levels, rather than a navigation tree.

- **The stroke is under the row**, outside its height, so a divided row is the row and its stroke:
  41 where an undivided row is 40.
- **To the panel's edges:** `bleed` takes the stroke and the open row's surface past the tree on each
  side while the rows stay where they are. Give it the panel's own inline padding, 16 in a
  `Container inset="panel"`; a number is pixels. Without it, both stop at the tree's edges.
- **The fills keep their corners.** A hover or selected fill stays rounded, inside the tree, over the
  surface. The focus ring is drawn inside the row, so neither the next row nor the panel's edge cuts
  it.
- **Composed trees:** rows put in a divided `Tree` as children are divided too. `TreeItemRow`,
  `TreeParentItemRow` and `TreeChildItemRow` also take `divided` of their own, which wins.

SwiftUI's `KozmosTree` and Compose's `KozmosTree` and `TreeItem` take `divided` and `bleed` from
0.16.0 (decision 134), with the same stroke, the same open row's surface and the same reach. A
divided SwiftUI tree draws its own rows rather than a `List`'s, so the strokes are Kozmos's, not the
list's separators, and an open parent says "Expanded" to VoiceOver.

## Sections, ranges and a menu

Pointr Cloud's Map Content tree holds thousands of items under a level, in sections, and is selected by range
(GAP-151, decision 132). Its real size is 13,031 items in one tree.

- **Sections:** an item with `section: true` is a heading, its name in the theme's colour with its `count`, over its
  `children`, which are drawn at the section's own depth. A section is always open and is never focused or selected:
  the keyboard and a range pass over it. Its items are a set of their own (`aria-setsize`, `aria-posinset`) in a
  `role="group"` named by the section and its count, "POI, 3,257" (a number count is formatted for the reader's
  locale); the heading itself is for the eye. Give `textValue` where `name` is not plain
  text. To compose one, `TreeSectionRow` is the heading.
- **A set of rows:** `selectionMode="multiple"` with `selectedIds` (or `defaultSelectedIds`) and
  `onSelectedIdsChange`. A click selects one row; Ctrl or Cmd with a click adds or takes away a row; Shift with a click
  selects the rows from the last one chosen, and Ctrl or Cmd with Shift adds them. By keyboard, Shift with the arrows,
  Home and End selects as focus moves, Space adds or takes away the focused row, Shift+Space selects to it and Ctrl or
  Cmd+A selects every row in view: the enabled rows, not those inside a closed parent. Ranges pass over disabled rows
  and headings. Closing a parent lets go of the rows it hides, in one `onSelectedIdsChange`, so a selection never
  holds a row nobody can see. The tree is `aria-multiselectable`.
  `"single"`, the default, is `selectedId` as before.
- **Type-ahead:** typing moves focus to the next row whose words start with what was typed, in every tree; the same
  letter again moves on to the next row that starts with it. It runs after a `onKeyDown` of yours on the Tree, and not
  when yours called `preventDefault()`; it takes no key with Ctrl, Cmd or Alt, never `+`, `-` or `*`, and leaves a key
  that finds no row alone.
- **More keys:** `*` opens every row beside the focused one that has rows of its own; PageDown and PageUp move focus by
  a page of rows (with Shift, in a multiple tree, the range goes with it).
- **Only the rows in view:** `virtualized` draws the rows in view, a few more each side (`overscan`, 8), and the focused
  row wherever it is. The tree scrolls itself, so give it a height. Each row's level and place in its set come from
  `data`, so a screen reader hears "3 of 9,000" and the keyboard, Home, End and type-ahead reach rows out of view.
  A row's height is measured once drawn; until then it is estimated from the density, `divided` and `metaPlacement`.
  Composed children are never virtualised.
- **Give it a height.** A virtualised tree with no height of its own is as tall as its rows and draws every one. Give
  it one (`style={{ height: 480 }}` or a class), or, in a flex column, `flex: 1` with `min-height: 0` (`min-h-0`), so it
  scrolls itself. In development it warns once in the console when it has none.
- **Divided and bled:** a virtualised tree that is `divided` with a `bleed` reaches the bleed itself, so its strokes
  meet the panel's edges with no sideways scroll; a virtualised tree draws its focus ring inside the row, where its own
  edge cannot cut it.
- **A menu on a row:** wrap the Tree in Kozmos's `ContextMenu` (`ContextMenuTrigger asChild`) and pass
  `onItemContextMenu`. A right click, a long press, or the menu key or Shift+F10 at the focused row, focuses the row
  and, if it is not selected, selects it alone, then calls `onItemContextMenu` with it, so the menu acts on the
  selection. With no `onItemContextMenu`, a right click leaves the selection alone.
- **Meta below the name:** `metaPlacement="below"` (on Tree, or a row of its own) draws a row's `meta` on a line under
  its name, so the name keeps the row's width: 'Bean & Leaf Café' whole, with 'Changes Awaiting Publish' under it
  (GAP-107). `"inline"`, the default, keeps the meta after the name.

SwiftUI's `KozmosTree` and Compose's `KozmosTree` take the same: sections (`Node.section` / `TreeNode(section = true)`),
a selection mode and a set of selected ids, `metaPlacement`, and a menu per row through the platform's Kozmos context
menu, over a lazy list of the rows in view. A tap in a multiple SwiftUI tree adds or takes away a row, as touch has no
Command key; with a pointer and keyboard, Shift selects a range and Command (Ctrl on Android) one row more.

**Migrating a SwiftUI tree (0.16.0):** `KozmosTree` no longer draws a `List`. Divided or not, a tree is Kozmos's own
lazy rows, with no list separators, inset grouping or grouped background, so an undivided tree looks as React's does
rather than as a system list. `Node.id` is a `String` (a UUID string when none is given), not a `UUID`: read it as a
string. SwiftUI and Compose ship from the repository's source, so this changes at the commit an app pins. Closing a
parent lets go of the rows it hides on every platform, and a section is heard with its count, "POI, 3,257".
