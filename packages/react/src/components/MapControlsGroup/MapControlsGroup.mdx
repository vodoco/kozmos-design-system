# MapControlsGroup

The stacked zoom, compass, and locate affordances that sit over a map.

## Usage

Use it as the standard control cluster on any map surface:

- Inside the `AdaptiveMapShell` controls slot
- Over a `MapView` in a custom layout

Each handler is optional, and omitting one removes its button. A map with fixed
zoom simply does not pass `onZoomIn` / `onZoomOut`, rather than rendering
disabled controls.

`compassBearing` rotates the compass glyph. Pass the renderer's current bearing;
the component does not track it.

`locationState` is a `UserLocationState` — `off`, `locating`, `following`,
`heading`, `permission-denied`, `stale`, or `unavailable`. Several of these are
not errors and should not read as failures: `locating` is in progress, and
`stale` still has a usable last-known fix.

Pair `locationState` with a localized `locationStateLabel`. The visual treatment
alone does not tell a screen reader user whether location is following, denied,
or merely stale.

### The location control's marks

The location control draws a mark for each state, from Pointr's Location
Tracking Buttons revamp:

| State                                   | Mark                                                      |
| --------------------------------------- | --------------------------------------------------------- |
| `off`, `stale`                          | the outline pointer                                       |
| `locating`                              | the outline pointer, with the button's spinner            |
| `following`                             | `LocationFollowing` — the solid pointer and its cone      |
| `heading`                               | `LocationHeading` — the upright pointer and the turn arc  |
| `permission-denied`, `unavailable`      | the pointer struck through                                |

The two symbols come from `@kozmos-ds/icons` and take the control's colour, so
they tint with it when pressed. To draw your own mark for a state, pass that
state in `locationIcons`; the others keep the group's marks.

### The SDK's location control

The SDK's control is icon-only over the map and widens to say its new mode for a
moment when the mode changes — "Focus / On", the state set under the name. Ask
for that with `locationRevealOnChange` and `locationLabelPlacement="stacked"`.
Both are off by default, so a product that relies on a fixed presentation sees
nothing move.

Give `heading` its own `locationStateLabel` rather than a second "On": the name
is all a screen reader has to tell following from a map that turns.

### Step-free during wayfinding

While a route is shown, a step-free control takes the location control's place.
Passing `onStepFreeChange` draws it, and the location control is not drawn; leave
it out once the route is gone and the location control returns. It reads as the
location control does — it follows `locationPresentation`,
`locationRevealOnChange` and `locationLabelPlacement` — so the corner keeps its
character between exploring and wayfinding.

Set `stepFree` once the route it describes is the one on the map. The name and
its two states are `stepFreeLabel`, `stepFreeOnLabel` and `stepFreeOffLabel`
("Step-free", "On", "Off"), for the product to translate.

## Accessibility

- Every control keeps a 44px target, including in the icon-only presentation,
  so the group satisfies the shared touch-target contract.
- `label` names the cluster so it is announced as one group of controls rather
  than a run of unlabelled buttons.
- `locationState` must be conveyed through `locationStateLabel`, not by the icon
  treatment alone. The marks are decorative: the button's name carries the state.
- The step-free control is a toggle: it reports `aria-pressed`, and its name
  carries its state ("Step-free, On"), as the location control's does.
- The compass glyph does not auto-mirror in RTL; a bearing is physical.
