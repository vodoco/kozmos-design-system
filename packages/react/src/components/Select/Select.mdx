# Select

Displays a list of options for the user to pick from—triggered by a button.

## Usage

Use a Select component when:
- Users need to choose a single option from a list.
- Space is limited (dropdown vs radio group).
- The list of options is static or small (< 20 items).

import SwiftUI
import Kozmos

// KozmosSelect is the system menu around a trigger you draw; each item
// sets the selection and ticks itself when it is the one chosen.
struct ThemeSelect: View {
    @Binding var theme: String

    var body: some View {
        KozmosSelect {
            Text(label)
        } content: {
            KozmosSelectItem(value: "light", label: "Light", selection: $theme)
            KozmosSelectItem(value: "dark", label: "Dark", selection: $theme)
            KozmosSelectItem(value: "system", label: "System", selection: $theme)
        }
    }

    // The trigger shows the choice, or what is being chosen until there is one.
    private var label: String {
        switch theme {
        case "light": return "Light"
        case "dark": return "Dark"
        case "system": return "System"
        default: return "Theme"
        }
    }
}
`}
    kotlin={`
import androidx.compose.material3.ExperimentalMaterial3Api
import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue
import com.kozmos.components.select.KozmosSelect
import com.kozmos.components.select.KozmosSelectItem
import com.kozmos.components.select.KozmosSelectTrigger

// KozmosSelectTrigger is the closed field: the choice, or the placeholder
// until there is one, beside a caret. It anchors the menu, which
// KozmosSelect draws. An item hands on its value, then asks for the menu to
// close.
@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun ThemeSelect(theme: String, onThemeChange: (String) -> Unit) {
    var expanded by remember { mutableStateOf(false) }
    val themes = mapOf("light" to "Light", "dark" to "Dark", "system" to "System")
    KozmosSelect(
        expanded = expanded,
        onExpandedChange = { expanded = it },
        trigger = {
            KozmosSelectTrigger(value = themes[theme], placeholder = "Theme")
        }
    ) {
        themes.forEach { (value, label) ->
            KozmosSelectItem(
                value = value,
                label = label,
                onValueChange = onThemeChange,
                onDismissRequest = { expanded = false }
            )
        }
    }
}
`}

### Option counts

`SelectItem` takes a `count`, drawn as a neutral Counter at the option's end, before the check's place, which every row keeps, so the counts form one column that a new choice never moves (GAP-164). It sits outside the item text, so the closed select shows the option's words alone. A number is written in the app's grouping, from the document's `lang` as Calendar reads it ("1,234"; "1.234" in German), and the option is named by its words, then its count: "POI, 96", whatever the words are. An `aria-label` you give the item wins. Open the select to see the counts; the story `Option counts, open` draws the list open.

<Canvas of={SelectStories.OptionCounts} />

SwiftUI's `KozmosSelectItem(value:label:count:selection:)` shows the count, grouped, as the system menu item's subtitle, and VoiceOver reads "POI, 96"; Compose's `KozmosSelectItem(..., count = 96)` draws a neutral `KozmosCounter` at the row's end and TalkBack reads "POI, 96". On every platform the closed select shows the label alone. In Figma, Select's open list shows `Option N Count` under `Show Counts`; the SwiftUI and Compose Code Connect snippets write fixed counts (128, 96, 32), because Figma's count text is not carried into a native snippet, whose `count` is a number.
