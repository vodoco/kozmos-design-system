# MultiSelect

A filterable field for choosing several options, each shown as a removable chip.

## Usage

Use it when the user picks more than one value from a long list:

- Filtering results by several categories at once
- Assigning multiple owners, tags, or amenities
- Any set-valued field where the choices are known up front

For one value use `Combobox`. For a handful of options with no filtering, a
group of `Checkbox` controls is clearer than a dropdown.

`maxSelected` caps the selection; the remaining options become unselectable
rather than disappearing, so the user can see what they are trading away.
Reaching it is said to a screen reader; pass `maxSelectedLabel` with your
translation:

```tsx
<MultiSelect
  label={t("amenities.label")}
  options={amenities}
  maxSelected={3}
  maxSelectedLabel={(max) => t("amenities.limit", { max })}
/>
```

`onValueChange` receives both the values and the matching options, so the label
for each chip does not need a second lookup.

Removing a chip, or clearing every choice with the clear button, hands focus to
the field: the button pressed goes with what it removed. After a clear the
field's list stays closed, since the visitor cleared the choice and did not ask
for options; typing or an arrow key opens it.

The clear and open buttons are Combobox's: each as tall as the field, 44 at
touch density and 40 at compact, at the field's end in either direction. On
one line the field keeps its height. The buttons keep the field's end free, so
each line has 16px less room for chips than it had with the older 28px buttons
(4px less without the clear), and chips wrap that much sooner. A `className`
with `p-*` or `pe-*` replaces that space, and the chips and text then run
under the buttons, as text does on Combobox.

## Media and trailing words

An option's leading `media`, an Avatar with its image or initials (decision 215), and its `trailing` words (GAP-260)
are drawn in the list as Listbox draws them, on every platform: see Listbox's "Media, trailing words and an active
option the product moves". The label stays the option's name, and is what a choice puts in the field.

## Groups

Give options a `group` and they are listed under their groups (GAP-192), as Combobox
lists them: options with no `group` first, unlabelled, then the groups in the order they
first appear, each under its label, drawn as `SelectLabel` draws its own. Filtering keeps
a group's label while any of its options matches and drops it when none does. Each group
is a `role="group"` named by its label; the label is not an option, and the arrow keys
move through the options in the order they are drawn, never onto a label. MultiSelect has
no Home or End. Pressing a label, or the list's padding, leaves the list open and focus in
the field. SwiftUI and Compose do not group yet.

## Mixed

With several features selected, an array property whose values differ is one field for all of
them (GAP-255, decision 188). `mixed` says the field stands for those values: it shows no chips,
"Multiple values" (`mixedLabel`) in their place as the empty field's placeholder, which a screen
reader says once with it, and opening it shows no option chosen. There is nothing to clear, and
Backspace removes nothing. A choice is the edit: the field reports that one option, chosen from
none, and the product clears `mixed`, so the field keeps its mixed state until something is chosen.
`onResetMixed` draws "Reset to multiple values" (`resetMixedLabel`) under the field once it is
no longer mixed, never while it is disabled or read-only; pressed, the typed query goes, the list
closes, focus goes back to the field, and the product drops the edit and sets `mixed` again. An
uncontrolled MultiSelect drops the choice it held as it turns mixed. SwiftUI's `KozmosMultiSelect`
and Compose's take the same props, as Input, NumberInput, Select and Combobox do (GAP-153).

A choice from a mixed field replaces every feature's choices with the one chosen, as a typed name
replaces every feature's name in Input: the field has no way to add one option to each feature's own.

In Figma, Mixed is a value of the State axis, as on Input and Combobox, so a mixed field that is also
disabled, read only or in focus cannot be drawn. A Mixed variant has no Reset Mixed layer; Mixed Text
and Reset Mixed Text hold the words, for a board in another language. MultiSelect's Mixed variants draw no chips whatever their Content, and Mixed with Open
checks no option.

import { useState } from "react";
import { MultiSelect } from "@kozmos-ds/react";

const options = [
  { value: "lift", label: "Lift" },
  { value: "toilets", label: "Toilets" },
  { value: "wifi", label: "Wi-Fi" },
];

// Each selected feature's facilities; where they differ, the field shows
// "Multiple values" and no chips, and a choice is the edit for them all.
export function FacilitiesAcrossSelection({ facilities }: { facilities: string[][] }) {
  const [edit, setEdit] = useState<string[] | undefined>(undefined);
  const differs = facilities.some((values) => values.join() !== facilities[0].join());
  return (
    <MultiSelect
      label="Facilities"
      options={options}
      value={edit ?? (differs ? [] : facilities[0])}
      mixed={differs && edit === undefined}
      onValueChange={setEdit}
      onResetMixed={differs ? () => setEdit(undefined) : undefined}
    />
  );
}
  `}

import { computed, ref } from "vue"

const props = defineProps({ facilities: Array })
const options = [
  { value: "lift", label: "Lift" },
  { value: "toilets", label: "Toilets" },
]
const edit = ref(undefined)
const differs = computed(() =>
  props.facilities.some((values) => values.join() !== props.facilities[0].join()),
)
</script>

<template>
  <KozmosMultiSelect
    label="Facilities"
    :options="options"
    :value="edit ?? (differs ? [] : facilities[0])"
    :mixed="differs && edit === undefined"
    @valueChange="(values) => (edit = values)"
    @resetMixed="edit = undefined"
  />
</template>
  `}
  swift={`
import SwiftUI
import Kozmos

struct FacilitiesAcrossSelection: View {
    let facilities: [[String]]
    let options: [KozmosListboxOption]
    @State private var edit: [String]?
    @State private var query = ""

    var body: some View {
        let differs = Set(facilities).count > 1
        KozmosMultiSelect(
            selectedValues: Binding(get: { edit ?? (differs ? [] : facilities[0]) }, set: { edit = $0 }),
            searchValue: $query,
            options: options,
            label: "Facilities",
            mixed: differs && edit == nil,
            onResetMixed: differs ? { edit = nil } : nil
        )
    }
}
  `}
  kotlin={`
import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue
import com.kozmos.components.listbox.KozmosListboxOption
import com.kozmos.components.multiselect.KozmosMultiSelect

// Each selected feature's facilities; where they differ, the field shows
// "Multiple values" and no chips, and a choice is the edit for them all.
@Composable
fun FacilitiesAcrossSelection(facilities: List<List<String>>, options: List<KozmosListboxOption>) {
    val differs = facilities.distinct().size > 1
    var edit by remember(facilities) { mutableStateOf<List<String>?>(null) }
    var query by remember { mutableStateOf("") }
    KozmosMultiSelect(
        selectedValues = edit ?: if (differs) emptyList() else facilities.first(),
        onValueChange = { edit = it },
        searchValue = query,
        onSearchValueChange = { query = it },
        options = options,
        label = "Facilities",
        mixed = differs && edit == null,
        onResetMixed = if (differs) ({ edit = null }) else null
    )
}
  `}
/>

## Accessibility

On SwiftUI and Compose the field itself says it is read only and says its error (GAP-235, GAP-236): Compose
puts "Read only" in the field's state description (`readOnlyLabel`, for the product's own words) and the error
message as the field's `error`; SwiftUI says "Read only", then the error message, as the field's accessibility hint
(`readOnlyLabel` too). SwiftUI still draws a read-only field disabled, so VoiceOver also says it is dimmed.

- Each chip carries its own remove button with an accessible name naming the
  value, so "Remove Food" is announced rather than "Remove".
- Backspace in an empty input removes the last chip, matching the behaviour
  keyboard users expect from token fields.
- `emptyText` is announced whenever the popup shows it (typing empties the
  list, or the list opens with nothing in it), by a status in the field that is
  there from the first render, as Combobox's is. The popup's copy is plain text,
  so it is said once.
- Reaching `maxSelected` disables the remaining options rather than hiding them,
  and the arrow keys pass over them. A screen reader is told politely, once:
  "Limit of 3 reached" by default, or the words `maxSelectedLabel` returns for
  the limit, in the product's language. A status of its own says it, in the
  field from the first render and empty, so only its words change. A value
  the host sets that reaches the limit, or goes past it, is said too. It is
  not said again while the selection stays at the limit, unless the limit or
  its words change (a new `maxSelected` or `maxSelectedLabel`, say for another
  language), nor for a field that mounts already there or is given a limit it
  already meets. Removing a choice clears it, and reaching the limit again
  says it again.
