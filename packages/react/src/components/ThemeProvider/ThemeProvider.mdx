# ThemeProvider

Scopes light, dark or system appearance, reading direction and token overrides to a Kozmos subtree and its owned portals.
It does not switch the host document's theme; persistence is opt-in through `storageKey`, or owned by the caller in controlled mode.

## Density

`density` sets how large the controls are inside the provider and its portals; a nested provider inherits it unless it names its own (decision 82).

- **`touch`**, the default, keeps today's sizes, as products and the SDK draw them: buttons, icon buttons and fields 44, the large icon button 48. Parts with a smaller size of their own keep it at both densities: MultiSelect's clear and open buttons and the small Chip are 28.
- **`compact`** is for pointer-first desktop tools such as Pointr Cloud. Buttons are 32, 40 and 48; icon buttons 28, 32 and 40; single-line fields 40: Input, Select, Combobox, MultiSelect, NumberInput, PasswordInput, and DatePicker, DateRangePicker, TimePicker, Search and ColorPicker, which are drawn on Input's recipe. Combobox's clear and open, NumberInput's steppers and PasswordInput's show-password button are as tall as the field; MultiSelect's clear and open stay 28. It is web only; SwiftUI and Compose stay touch. Compact goes below 44, which suits a pointer, and keeps WCAG 2.2's 24 × 24 minimum target.
- **SDK parts keep the SDK's touch geometry** under any density (decision 89), so an SDK screen previewed in a compact page draws as the apps draw it. Each SDK part's root is a touch `DensityScope`, so a provider nested in it, the popovers it opens and what a product puts in its slots stay touch as well.
- **For one region at another density, wrap it in `DensityScope density="…"`.** Its controls, the providers inside it and the popovers it opens take that density, and the theme, its tokens and the design configuration around it carry on. Wrap your own content inside an SDK part the same way, such as a compact tool panel in `AdaptiveMapShell`. `asChild` marks your one element instead of adding one. A nested `KozmosTheme` would start its own design configuration, and a nested `ThemeProvider` its own theme.
- **Outside any provider** the controls draw at touch sizes.

The Density toolbar above the canvas shows any story at either density.

```tsx
<ThemeProvider density="compact">
  <Button>Publish</Button>
  <DensityScope density="touch">
    <Button>Tap target</Button>
  </DensityScope>
</ThemeProvider>
```

import SwiftUI
import Kozmos

// The provider follows the system until ThemeManager's selectedTheme, kept in
// the app's user defaults, says "light" or "dark". The scheme it sets is its
// presentation's, the window or sheet it is in, not this subtree's alone.
struct ThemedScreen: View {
    let onContinue: () -> Void

    var body: some View {
        KozmosThemeProvider {
            KozmosButton("Continue", action: onContinue)
        }
    }
}
`}
    kotlin={`
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import com.kozmos.components.button.KozmosButton
import com.kozmos.components.themeprovider.KozmosThemeProvider

// The provider starts with the system's theme. Inside it,
// LocalThemeManager.current.setThemeMode(KozmosThemeMode.DARK) changes the
// theme of its content; the choice is not saved.
@Composable
fun ThemedScreen(onContinue: () -> Unit) {
    KozmosThemeProvider {
        KozmosButton(onClick = onContinue) { Text("Continue") }
    }
}
`}
