# Combobox

A single-select field that filters its options as the user types.

On React, an open suggestions popup owns the first Escape, including inside Core
Dialog, Popover or the assistant panel. It closes only the suggestions and keeps
focus on the input; a later Escape can dismiss the enclosing surface. This also
applies to inline popups and empty results. A host `onKeyDown` that prevents Escape,
or an IME-composing Escape, leaves both layers open. IME cancellation is not
prevented at the browser level. The field participates in the existing overlay
layer stack without portaling, adding focus traps or changing its placement.

## Usage

Use it when the list is too long to scan comfortably in a `Select` — roughly a
dozen options or more:

- Country, city, or venue pickers
- Assigning a person from a directory
- Any list where the user knows what they want and would rather type it

For a short, fixed list use `Select`; the filter input is overhead there. For
choosing several values use `MultiSelect`.

`onValueChange` receives both the value and the matching option, so there is no
need to look the option up again by id.

Set `emptyText` to something that tells the user what to do next — "No venues
match that name" beats "No results".

Disclosure and clear buttons use 44 px/pt targets on web/iOS and 48 dp on Android.
Use `clearLabel`, `openLabel` and `closeLabel` to localize these actions; Compose's
equivalent overload accepts `KozmosComboboxLabels`. Existing native calls remain valid.
The field keeps its accessible label when populated. SwiftUI options include their
secondary description in the accessible name, and selection writes its binding once.

When a host has already filtered and ranked suggestions, web can supply
`filterOption={() => true}`. SwiftUI accepts `filterLocally: false`; Compose's
explicit overload accepts both `controlLabels` and `filterLocally = false`.
Local substring filtering remains the default, and both previous Compose overloads
retain their positional and trailing-lambda signatures. For places, prefer
RouteLocationField's `filterMode` so identity and readiness guards remain in place.

`defaultInputValue` is an initial search draft, not a selected entity. A later selection
change updates uncontrolled display text. Controlled `inputValue` remains host-owned.

Web's existing generic `option_selected` analytics includes the value by default for
compatibility. Set `includeValueInAnalytics={false}` for sensitive values. RouteLocationField
does this automatically, so place IDs and search text are not sent in that event. Native
Combobox does not emit automatic selection-value analytics.

## Implementation

### React popup commands

Use `popupLayout="inline"` inside a content-sized or clipping sheet so the open dropdown
participates in layout and scrolling. The default remains `overlay` for existing consumers.

`popupActions` adds persistent commands below the filtered suggestions inside the popup.
Each has a stable `id`, localized `label`, optional decorative `icon`/`disabled`, and `onAction`.
IDs must be nonblank and unique among commands: all entries sharing a duplicate ID
are omitted, not resolved to an arbitrary callback. A command and location may share
the same string ID because their identities are separate.
These are separately typed action choices, not location values. They are
unfiltered and available with no matching results; they never update the selected value,
input text or option-selection analytics. Arrow keys navigate both suggestions and actions;
Enter activates the highlighted row. Escape closes the popup and returns focus to the input. An action
closes and restores input focus before invoking its callback, allowing a host to move focus
to a new map/dialog. Disabled/read-only fields cannot invoke them. Home/End reach the first/last
enabled choice.

Matching empty-state and supporting text is rendered once by the field, retaining
its accessible description. An empty popup with no commands adds no box or shadow;
its open state still owns the first Escape before an enclosing overlay can close.

### Native popup commands

SwiftUI and Compose also accept `popupActions: [KozmosPickerAction]` / `List<KozmosPickerAction>`.
Each command has a stable, nonblank, unique `id`, localized `label`, `disabled` flag and
callback (`action` in Swift, `onAction` in Kotlin). Blank and duplicate IDs are omitted.
Commands are rendered as Core ghost Buttons inside Core Listbox, below suggestions;
they remain available for unmatched queries and empty/error suggestion states. They
never write a selected value or query, or acquire selected-option semantics.
Identical supporting and empty-state text is rendered once, below the field/popup,
instead of repeating the same loading/error message. Native lists fit short content
and retain a height-capped scrolling viewport for longer results.

SwiftUI optionally accepts `expanded: Binding<Bool>`; Compose retains `expanded` and
`onExpandedChange`. User edits can open the picker; host query updates alone do not
reopen it after a selection or command. Commands request input focus and request closure **before** invoking
the callback. A controlling host must honour that closure request and owns focus in any
new map/dialog it opens. Disabled/read-only fields hide the popup even if forced open.
Native keyboard/assistive-technology behavior uses native controls; the React arrow-key
and overlay-layer implementation is not a claim of identical native behavior. Verify
VoiceOver/TalkBack, keyboard insets and focus transfer in the integrating application.

Compose's new action overload requires `controlLabels`, `filterLocally` and `popupActions`;
all three older overloads retain positional and trailing-lambda compatibility. Swift's
new parameters default to no commands and uncontrolled expansion.

## Accessibility

- The listbox is linked to the input, so the active option is announced as the
  user arrows through it.
- Typing filters but never silently changes the selection; committing is an
  explicit choice.
- `emptyText` is announced when filtering empties the list, so the absence of
  results is not conveyed only by an empty box.
