# Input

Inputs allow users to enter text into a UI. They typically appear in forms and dialogs.

## Usage

Use inputs to get text data from the user. Common use cases include:
- Forms (Name, Email, Password)
- Search fields
- Filtering data

## Actions

`action` puts a button inside the field's end (GAP-154), drawn as PasswordInput's reveal is: as tall
as the field, inside its border, with its own focus ring, and the field's text kept clear of it.
It is disabled with the field.

- `{ kind: "copy" }` copies the field's value: for a value a product shows and never edits, a
  feature's ID, with `readOnly`. Once copied, a polite live region says "Copied" (`copiedLabel`),
  and a check stands in for the copy icon for two seconds; copied again, it says so again. If the
  browser refuses the clipboard, it says nothing. The button is named "Copy" (`label`); `onCopy`
  receives the value.
- `{ kind: "toggle" }` is a pressed button with its own name: the Featured star at a field's end.
  `label`, `icon`, `pressed` and `onPressedChange` are the product's; pressed, the icon is drawn in
  the theme's colour, so the state shows whatever the icon.

## In Safari

`className` lands on the field. A utility class passed there styles it in Chrome, Edge,
Firefox and Safari 26.4, and is ignored in Safari 26.0 to 26.3, where the field keeps its
own look: those versions apply no `@scope` rule to an `<input>` (GAP-174), and Kozmos's
utilities are scoped. Use the props, the provider's `tokens`, an inline `style` or your
own CSS, and `wrapperClassName` for the layout around it. Guides › Platform support ›
Fields in Safari has the detail.
