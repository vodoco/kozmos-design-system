# Route Summary

<Canvas of={RouteSummaryStories.Active} />

`RouteSummary` presents route estimates and actions. It is not a modal sheet or routing engine: the host owns sheet placement, safe areas, focus, route state and routing logic.

On `surface="glass"` the distance, muted elsewhere, takes the foreground colour, so it reads at 4.5:1 over any map (decision 48). The navigation layout draws its text in the foreground colour already.

## React

```tsx
import { RouteSummary } from '@kozmos-ds/react';
import { NavigationPointer01 } from '@kozmos-ds/icons';

<RouteSummary
    etaText="7 min"
    distanceText="500 ft"
    state="active"
    transportModeIcon={<NavigationPointer01 />}
    onEndRoute={() => prompt("End Route Confirmation")}
/>
```

The estimate layout's words are the product's to translate, on every platform: `endRouteLabel` names the End icon button and `startNavigationLabel` is Start's label. SwiftUI and Compose take them under the same names, before the transport mode's trailing closure or lambda, and keep "End route" and "Start Navigation" when they are left out. On Compose, End keeps Material's 48dp touch target.

## Navigation

Given a `destination`, the summary takes the navigation layout: the destination's name with End beside it in the danger outline, the time, distance and arrival on one row, and the caller's progress — a `RouteProgressRail` in the products — below. The estimate layout above is unchanged.

<Canvas of={RouteSummaryStories.Navigation_} />

Hosted removes the summary's outer padding, surface, radius and shadow. Left unset, `presentation` is hosted in `AdaptiveMapShell`'s panel, whose surface is the one surface there (decision 43), and standalone anywhere else, as before. Pass `presentation="hosted"` inside a sheet of your own, or `"standalone"` to keep the card in the shell. Navigation metrics are optional and represent remaining estimates, not actual journey totals. Omitted values stay absent; supplied zero-valued labels stay visible. `destinationImage` is decorative and retains its fixed-size fallback on failure. Long destination names wrap without a two-line clamp.

Swift and Compose follow the same rule: left out (`nil` or `null`), `presentation` is hosted in the map shell's panel and standalone elsewhere; `.hosted` or `KozmosRoutePresentation.Hosted` and their standalone counterparts choose. Compose retains the original navigation overload for positional source compatibility, and it follows the shell too. The estimate layout has no hosted presentation on any platform and is unchanged.

## Actions

The navigation layout takes `actions` after its progress: the journey's own actions, Previous and Next in static wayfinding (Step-by-Step, and the web fallback, which has no live position). Live guidance draws none. Kozmos owns the row's layout: equal columns in reading order, so in a right-to-left language Previous sits on the right, each as tall as the tallest. A Kozmos Button there fills its column, grows to two lines rather than overflow, and keeps its 44px (Android's 48dp touch target included). The words are text only, as on the boards; an arrow, if a product adds one, must be logical, so that it mirrors.

The host draws the buttons and owns what they do:

- Each Button says `type="button"`. Button has no default type, so inside a form one would submit it.
- At the ends of the route, a step control is unavailable through `aria-disabled="true"` and a handler that does nothing, not `disabled`. A button disabled under the pointer drops the focus to the page; Previous on the first step keeps it. The row draws `aria-disabled` at the disabled button's 50%. SwiftUI and Compose disable the button, which keeps VoiceOver's and TalkBack's focus where it was.
- The new step is said by the host's `NavigationAnnouncer`, the one announcement owner. The summary says nothing itself.
- Whether the last step disables Next or turns it into Finish, leading to arrival, is the product's choice; the row takes either.

## Route preview

Without `onEndRoute` the navigation layout draws no End: it is the route preview, the destination's card before the journey starts. `locationText` adds the place's line under the destination, muted, and on glass the foreground colour (decision 48). Go and Details sit in `actions`, Go first. Details shows the route's directions in the same panel, which the host composes: a Back button, a heading, the `Itinerary` and Go. The estimate layout keeps `onEndRoute` required.

On SwiftUI the preview passes `progress: { EmptyView() }`, because the progress stays the initializer's trailing closure. On Compose `actions` comes before `progress`, so a trailing lambda is still the progress, and the original overload keeps its positional parameters.

import { useState } from "react";
import {
  Button,

// Static wayfinding: Previous and Next in the summary's actions. The host
// owns the step, makes the ends unavailable without losing focus, and says
// the new step through its announcer, the one announcement owner.
export function StepByStepSummary({
  steps,
  onEnd,
}: {
  steps: string[];
  onEnd: () => void;
}) {
  const [step, setStep] = useState(0);
  const first = step === 0;
  const last = step === steps.length - 1;
  return (
    <>
      <RouteSummary
        destination="Airport Shuttles"
        durationText="4 min"
        distanceText="201 m"
        onEndRoute={onEnd}
        progress={
          <RouteProgressRail
            progress={step / Math.max(steps.length - 1, 1)}
            type="straight"
            label={steps[step]}
          />
        }
        actions={
          <>
            <Button
              type="button"
              variant="outline"
              aria-disabled={first || undefined}
              onClick={() => {
                if (!first) setStep(step - 1);
              }}
            >
              Previous
            </Button>
            <Button
              type="button"
              aria-disabled={last || undefined}

              Next
            </Button>
          </>

}
