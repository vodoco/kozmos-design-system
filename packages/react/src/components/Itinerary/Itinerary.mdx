# Itinerary

The whole route as a list: where it starts, every step with the current one emphasised, where it ends. The steps are the routing engine's own words, each with the mark Kozmos draws for its type; the origin and destination sit under their labels. Assistive technology reads the endpoints with their labels and each step as one item, the current one marked as such.

Endpoint captions grow with localized text instead of being forced into a 40-unit column. The endpoint moves onto another line when needed; long place names remain visible rather than being limited to two lines. The host owns the itinerary's scroll container.

On a glass surface, in a glass `ManoeuvreCard`, the captions and the origin, muted elsewhere, take the foreground colour, so they read at 4.5:1 over any map (decision 48).

## Instruction wording and language

Each step's `instruction` accepts a legacy string or ordered `{ text, role?, lang? }`
parts. A `secondary` qualifier is muted and regular-weight without shrinking its
font; a `lang` value preserves a foreign landmark's speech language. Supply exact
spaces and punctuation, including German/Japanese qualifiers in their correct position.
The current-step state stays independent of these text styles.

The host must supply at most one current step and stable unique step IDs. If several
steps are marked current, none is emphasized or announced as current; the component
does not choose an arbitrary step. Correct the host snapshot rather than relying on
this defensive fallback to repair a route.

Each step also accepts optional localized `distance` and `duration` labels. These
are estimates for that step, not remaining-route estimates or actual arrival totals.
Either label can stand alone; missing/empty labels draw nothing, while a supplied
`"0 min"` is kept. Metrics appear below the instruction and are read after it without
discarding speech-language metadata. Native initializers and Kotlin copy operations
accept the same optional fields, retaining the original positional arguments.

SwiftUI/Compose accept arrays/lists of `KozmosInstructionPart` through the itinerary
step's overloaded initializer/constructor. Their `instruction` String accessor remains;
`instructionParts` preserves the canonical metadata. Kotlin's existing copy and
destructuring calls remain source-compatible: copying only current state retains parts,
whereas `copy(instruction = "new words")` resets to plain text. Recompile native callers
after upgrading; native binary compatibility is not promised by this source change.
