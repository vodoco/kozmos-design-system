# POIResultList

Controlled list composition that keeps result selection synchronized by POI ID.
`resultCountLabel` is localized by the consumer and announced when results
change. The empty state should tell the person how to recover.

## The selected result comes into view

When `selectedPoiId` changes, the list brings that result into view: a pin's
tap selects a result that may be anywhere in the list. It scrolls the nearest
thing around it that scrolls, by the least distance, and nothing further out —
never the map sheet's frame, the shell, or the page when something closer
scrolls. With nothing around the list that scrolls, it scrolls the page.

A box that hides its overflow counts only when it says it scrolls, with
`data-kozmos-scroller`. `AdaptiveMapShell`'s sheet does: below its largest
detent it hides its overflow and a finger cannot scroll it, but the list can.
Any other box that hides its overflow is clipping, and is left alone.

- A list that appears with a result already selected, as when a pin's tap
  opens it, brings that result in too.
- A selection that comes before its results, as when a pin's tap arrives while
  they are still loading, waits for them: the list brings the result in when a
  batch of `items` has it.
- Each selection is brought in once. A new array of the same results, as a
  product that builds `items` in its render passes every time, moves nothing;
  a result that leaves the list and comes back is brought in again.
- A selected card opens its action row as it animates, so the list brings it in
  again once the row is open.
- A result inside a collapsed group brings in its group.
- With reduced motion the list jumps rather than glides.

Pass `scrollSelectedIntoView={false}` if the product already scrolls the panel
itself. A selection made while it is off waits too: turned back on, the list
brings in the one it has not brought in yet.

## More than one list on a page

Each result card's id comes from its place's id, `getPOIResultDomId(poiId)`,
so a map pin can say which card it controls: `LocationPin`'s `resultId`. A page
that shows the same place in two lists — the search's results and an
assistant's answer — would draw that id twice, and the second card's action row
and unavailable note would be found in the first list. Give each list but one
an `idPrefix`: every id in it becomes `getPOIResultDomId(poiId, idPrefix)`, and
its references stay inside it. Keep the prefix the same on the server and in
the browser: a word, or an id from `useId()`.

```tsx
<POIResultList idPrefix="assistant" items={answer} {...rest} />

<LocationPin resultId={getPOIResultDomId(poi.id, "assistant")} {...pin} />
```

Without `idPrefix` the ids are what they have always been, so existing pins
keep finding their cards. A card of its own, outside a list, takes the same
`idPrefix`, and an `id` given to it outright wins.

## At the top of a map sheet

The list brings no padding of its own; whatever holds it pads it. At the top of
`AdaptiveMapShell`'s sheet, under the grip, it keeps the grip's 4px clearance
(`--kozmos-panel-clearance-top`), so its first result stays out of the grip's
target circle (WCAG 2.5.8). Anywhere else it adds nothing.

On a glass surface its empty state's text, muted elsewhere, takes the
foreground colour, so it reads at 4.5:1 over any map (decision 48). Its results
are cards of their own, with their own fill, and keep their muted text.
