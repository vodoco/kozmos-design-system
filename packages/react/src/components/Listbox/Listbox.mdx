# Listbox

An always-visible list of selectable options, in single or multiple mode.

## Usage

Use it when the options should stay on screen rather than hide behind a trigger:

- A filter panel beside results
- A settings pane where the current choice should always be readable
- The list body inside a larger composed control

If the list should collapse to a trigger, use `Select`, `Combobox`, or
`MultiSelect` — those own their own popover. `Listbox` is deliberately just the
list, so it composes inside them and inside your own surfaces.

`onValueChange` receives the new value and the option that caused the change. In
`multiple` mode the value is an array; in single mode it is a string. Read the
mode from your own state rather than inferring it from the value's type — an
array of one is ambiguous otherwise.

Native Listbox accepts optional `actions` (`KozmosPickerAction`) and `emptyText`.
Commands use Core Buttons and never change selected values. Their IDs must be
nonblank and unique; disabled commands remain visible but inert. The containing
Combobox, rather than Listbox itself, owns closing and input-focus requests.
`maxHeight` is a scrolling cap, not a fixed height: short lists hug their content,
including when long results are replaced by a short or empty set. Long lists keep
their scrolling viewport and their commands remain reachable by scrolling.

## Groups

Give options a `group` and they are listed under their groups (GAP-192), each group's
options together under its label, drawn as `SelectLabel` draws its own, in the order the
groups first appear in `options`. Each group is a `role="group"` named by its label; the
label is not an option, and the arrow keys, Home and End move through the options in the
order they are drawn, never onto a label, and a group's label comes into view with its
first option. Options with no `group` come first, unlabelled, before every group; a group's
name is trimmed, and a blank one is no group. Combobox and MultiSelect take the same
`group`; SwiftUI and Compose do not group yet.

## Embedded

A Listbox draws its own panel: a border, the popover surface, the overlay shadow and 12 of padding. Inside a container
that is already the box, a Dialog, a Popover or a Card, that is a box inside a box, as Switch client had it (GAP-271,
decision 186). `embedded` draws no panel of its own: no border, no surface, no shadow and no padding, so its rows sit
at the container's own inset. The rows, their fills, the keyboard and the focus ring are as they are.

SwiftUI's `KozmosListbox(embedded: true)` and Compose's `KozmosListbox(embedded = true)` draw the same.

## Media, trailing words and an active option the product moves

An option takes a leading `media` (decision 215, GAP-282): the Avatar's `sm`, 24 (decision 221), so a row with a
logo keeps the list's row height, with the option's
image (`src`, a client's logo) or its `initials` when it has none or until it loads, by default the label's first
letters ("PC" for "Pointr Cloud"). It is decoration: the label stays the option's name. An option also takes
`trailing` (GAP-260), drawn muted at its end before the check, such as a property's type; it is the option's
description, so the option's name stays its label. Combobox and MultiSelect draw both in their lists, as Listbox does;
rows without them are unchanged.

`activeValue` with `onActiveValueChange` (GAP-260) hands the active option to the product, so a search field can drive
the list as a combobox, focus staying in the field: the field's `aria-activedescendant` names the active option by
`listboxOptionId(listboxId, options, value)`, the product moves `activeValue` on the field's arrow keys, and the list
asks for a move by its own keys and the pointer. `null` is no active option. SwiftUI's `KozmosListbox(activeValue:)`
and Compose's `KozmosListbox(activeValue =)` draw the product's active option with the hover fill, as React's; on SwiftUI
an option's trailing words are its accessibility hint, on Compose they are said after its label.

## Accessibility

- On React, renders as a listbox with `option` children, so selection state is announced
  rather than inferred from styling.
- Always supply a meaningful `aria-label` or `aria-labelledby`; an option's name
  does not name the listbox itself.
- Arrow keys move the active option and Home / End jump to the ends. Enter / Space
  commit selection; selection does **not** automatically follow focus.
- The default maximum height is 16rem; React has no `maxHeight` prop. Use `style`
  or your own CSS class to customize it.

SwiftUI exposes selected traits on option buttons; Compose uses selectable rows
with explicit selected state, including single and multiple modes. Native command
buttons do not become selected, even if a command and location have the same ID.
Native keyboard and VoiceOver/TalkBack acceptance must be verified in the host;
the web ARIA and keyboard contract above is not a claim of identical native behavior.
