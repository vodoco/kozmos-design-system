# DateRangePicker

The range adapts to its container width rather than the screen width: narrow
modules stack the individually labelled fields. The group heading names the range.
Each date's bounds respect both the sibling date and the caller's `min`/`max`.

A paired start and end date field for selecting a period.

## Usage

Use it wherever a span matters rather than a single day:

- Report and analytics ranges
- Booking and availability windows
- Filtering history by period

For one date use `DatePicker`. `DateRangePicker` is exported from the same
module and shares its validation and formatting behaviour.

On the web, values are ISO `YYYY-MM-DD` strings rather than `Date` objects, so
they survive serialization and carry no timezone of their own. Native uses each
platform's own date type — `Date` on SwiftUI, `LocalDate` on Compose — so
convert at the edges of your app rather than in the field.

`onRangeChange` fires when either end changes, including while the range is
incomplete — expect a value with one end still empty and do not treat that as
invalid input mid-edit.

## The range calendar

Each field keeps the browser's segmented typing, and a button at its end opens one panel for the
range under both fields: Kozmos's `Calendar` in range mode (decisions 104 and 105), drawn as
Figma's Open variant (`443:7567`), two months 12 apart where the window has room and one where it
has not (`months` picks). It opens on that field's day, else the range's start, else today; Alt+Down
Arrow or F4 in either field open it too. The first day chosen starts a range and clears the end, the
days under the pointer or the focus show where it would end, and the second closes it, both fields
filled, in order. Escape closes it with nothing changed, and focus returns to the button it opened
from. `open` with `onOpenChange` controls it, and `defaultOpen` opens it at first. The calendar is
modal, so this page shows it closed; Storybook's `Open` and `OneMonth` stories draw it open.

`chooseDatesLabel` names each field's button (`"Choose dates"`), and the field's label describes
it; `previousMonthLabel`, `nextMonthLabel`, `locale`, `today` and `isDateUnavailable` are the
calendar's, as DatePicker's are. A closed day cannot start or end the range; a range may cross one.
As DatePicker's, the panel replaces the browser's own picker only where that picker's button can
give way, read from the engine's CSS: in Chromium, Edge and Safari. In Firefox 146 both fields stay
the browser's, untouched, until Firefox can hide its button (Mozilla bug 2051201).

### One label for the range

`hideFieldLabels` reads the fields' labels to a screen reader and shows none, so the range's one
`label` names it in a one-line filter bar (GAP-051).

## Mixed

With several features selected, a range whose values differ is one field for all of them
(GAP-255, decision 188). `mixed` is one state for the range: neither end shows a date of its own,
both show "Multiple values" (`mixedLabel`) over their empty segments, as DatePicker does, and a
screen reader hears it once with each, as its description. The calendar opens on no range. A typed
or chosen end is the edit, reported with the other end empty, and the product clears `mixed`;
`onResetMixed` draws one "Reset to multiple values" (`resetMixedLabel`) under the range once it is
edited, never while it is disabled or read-only, and hands focus to the start. An uncontrolled range
drops the dates it held as it turns mixed.

SwiftUI's `KozmosDateRangePicker` and Compose's take the same props: both fields, and the range
preview where it shows, say "Multiple values", and one reset sits under the range.

In Figma, Mixed is a value of the State axis, as on Input and Combobox, so a mixed field that is also
disabled, read only or in focus cannot be drawn. A Mixed variant has no Reset Mixed layer; Mixed Text
and Reset Mixed Text hold the words, for a board in another language. Mixed draws Multiple values in both fields, and Mixed with Open a calendar with no range.

<PlatformSnippets
  react={`
import { useState } from "react";
import { DateRangePicker, type DateRangeValue } from "@kozmos-ds/react";

// Each selected feature's closure; where they differ, both ends show
// "Multiple values", and one reset under the range brings them back.
export function ClosureAcrossSelection({ closures }: { closures: DateRangeValue[] }) {
  const [edit, setEdit] = useState<DateRangeValue | undefined>(undefined);
  const differs = closures.some(
    (range) => range.start !== closures[0].start || range.end !== closures[0].end,
  );
  return (
    <DateRangePicker
      label="Closed"
      value={edit ?? (differs ? { start: "", end: "" } : closures[0])}
      mixed={differs && edit === undefined}
      onValueChange={setEdit}
      onResetMixed={differs ? () => setEdit(undefined) : undefined}
    />
  );
}
  `}
  vue={`
<script setup>
import { KozmosDateRangePicker } from "@kozmos-ds/vue/react-bridge"
import { computed, ref } from "vue"

const props = defineProps({ closures: Array })
const edit = ref(undefined)
const differs = computed(() =>
  props.closures.some(
    (range) => range.start !== props.closures[0].start || range.end !== props.closures[0].end,
  ),
)
</script>

<template>
  <KozmosDateRangePicker
    label="Closed"
    :value="edit ?? (differs ? { start: '', end: '' } : closures[0])"
    :mixed="differs && edit === undefined"
    @valueChange="(range) => (edit = range)"
    @resetMixed="edit = undefined"
  />
</template>
  `}
  swift={`
import SwiftUI
import Kozmos

struct ClosureAcrossSelection: View {
    let closures: [ClosedRange<Date>]
    @State private var start: Date?
    @State private var end: Date?

    var body: some View {
        let differs = Set(closures).count > 1
        KozmosDateRangePicker(
            startDate: Binding(get: { start ?? closures[0].lowerBound }, set: { start = $0 }),
            endDate: Binding(get: { end ?? closures[0].upperBound }, set: { end = $0 }),
            label: "Closed",
            mixed: differs && start == nil && end == nil,
            onResetMixed: differs ? { start = nil; end = nil } : nil
        )
    }
}
  `}
  kotlin={`
import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue
import com.kozmos.components.daterangepicker.KozmosDateRangePicker
import com.kozmos.components.daterangepicker.KozmosDateRangeValue

// Each selected feature's season; where they differ, both ends show
// "Multiple values", and one reset under the range brings them back.
@Composable
fun SeasonAcrossSelection(seasons: List<KozmosDateRangeValue>) {
    val differs = seasons.distinct().size > 1
    var edit by remember(seasons) { mutableStateOf<KozmosDateRangeValue?>(null) }
    KozmosDateRangePicker(
        value = edit ?: seasons.first(),
        onValueChange = { edit = it },
        label = "Season",
        mixed = differs && edit == null,
        onResetMixed = if (differs) ({ edit = null }) else null
    )
}
  `}
/>

## Accessibility

- Start and end are separate labelled fields, so each is announced on its own
  rather than as one ambiguous control.
- `min` and `max` bound both ends; an end before its start is reported through
  `error`, as a message rather than by colour.
- The range reads correctly in RTL because the two fields follow flow order.
- The calendar is a modal dialog named by the range's `label`: focus stays in it, and returns to
  the field's button it opened from. Each button is named by `chooseDatesLabel` and described by
  its field's label.
