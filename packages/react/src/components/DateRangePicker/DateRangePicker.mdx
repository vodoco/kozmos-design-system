# DateRangePicker

The range adapts to its container width rather than the screen width: narrow
modules stack the individually labelled fields. The group heading names the range.
Each date's bounds respect both the sibling date and the caller's `min`/`max`.

A paired start and end date field for selecting a period.

## Usage

Use it wherever a span matters rather than a single day:

- Report and analytics ranges
- Booking and availability windows
- Filtering history by period

For one date use `DatePicker`. `DateRangePicker` is exported from the same
module and shares its validation and formatting behaviour.

On the web, values are ISO `YYYY-MM-DD` strings rather than `Date` objects, so
they survive serialization and carry no timezone of their own. Native uses each
platform's own date type — `Date` on SwiftUI, `LocalDate` on Compose — so
convert at the edges of your app rather than in the field.

`onRangeChange` fires when either end changes, including while the range is
incomplete — expect a value with one end still empty and do not treat that as
invalid input mid-edit.

## The range calendar

Each field keeps the browser's segmented typing, and a button at its end opens one panel for the
range under both fields: Kozmos's `Calendar` in range mode (decisions 104 and 105), drawn as
Figma's Open variant (`443:7567`), two months 12 apart where the window has room and one where it
has not (`months` picks). It opens on that field's day, else the range's start, else today; Alt+Down
Arrow or F4 in either field open it too. The first day chosen starts a range and clears the end, the
days under the pointer or the focus show where it would end, and the second closes it, both fields
filled, in order. Escape closes it with nothing changed, and focus returns to the button it opened
from. `open` with `onOpenChange` controls it, and `defaultOpen` opens it at first. The calendar is
modal, so this page shows it closed; Storybook's `Open` and `OneMonth` stories draw it open.

`chooseDatesLabel` names each field's button (`"Choose dates"`), and the field's label describes
it; `previousMonthLabel`, `nextMonthLabel`, `locale`, `today` and `isDateUnavailable` are the
calendar's, as DatePicker's are. A closed day cannot start or end the range; a range may cross one.
As DatePicker's, the panel replaces the browser's own picker only where that picker's button can
give way, read from the engine's CSS: in Chromium, Edge and Safari. In Firefox 146 both fields stay
the browser's, untouched, until Firefox can hide its button (Mozilla bug 2051201).

### One label for the range

`hideFieldLabels` reads the fields' labels to a screen reader and shows none, so the range's one
`label` names it in a one-line filter bar (GAP-051).

## Accessibility

- Start and end are separate labelled fields, so each is announced on its own
  rather than as one ambiguous control.
- `min` and `max` bound both ends; an end before its start is reported through
  `error`, as a message rather than by colour.
- The range reads correctly in RTL because the two fields follow flow order.
- The calendar is a modal dialog named by the range's `label`: focus stays in it, and returns to
  the field's button it opened from. Each button is named by `chooseDatesLabel` and described by
  its field's label.
