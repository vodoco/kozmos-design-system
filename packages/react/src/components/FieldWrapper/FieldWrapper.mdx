# FieldWrapper

The label, description, helper text, and error message that surround a form
control — without the control itself.

## Usage

Use it when you build a field the library does not already provide:

- A custom control that needs the same label and error treatment as `Input`
- A third-party widget you want to sit correctly inside a Kozmos form
- A composed field grouping several controls under one label

You rarely need it directly. `Input`, `Select`, `Combobox` and the rest already
wrap themselves in it, and wrapping them again produces two labels.

The id props (`inputId`, `descriptionId`, `helperId`, `errorId`) exist so the
wrapper can wire `aria-describedby` to your control. Pass the same `inputId` you
give the control, or the association silently does not happen — the layout will
look right while screen readers announce an unlabelled field.

`error` accepts `true` for the error styling alone, or a string to also render
the message.

For several individually labelled controls, React's `group` prop makes the wrapper
a named ARIA group and renders its heading as text rather than a second input
label. Give each child its own label; do not pass `inputId` for the group.
`DateRangePicker` uses this mode for the range heading and keeps separate start/end
labels. This additive React prop does not imply equivalent native or Vue support.

## Accessibility

- This component is the reason the rest of the form controls are accessible;
  its whole job is the label and description wiring.
- Pass a matching `inputId` or the `aria-describedby` association is silently
  lost — the visual layout gives no hint that it failed.
- `hideLabel` hides the label visually but keeps it for assistive technology.
  Use it rather than dropping the label.
- `required` marks the field for assistive technology as well as visually;
  `optionalText` is the inverse convention if you mark optional fields instead.
