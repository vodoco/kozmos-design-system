# MapStatusPill

One status on the map, drawn as a compact pill in one of five tones (decision
39). The SDK draws three parts for this — PositionStatus, Downloading Content
and the Turn Back indicator — and the step-free route being calculated is a
fourth (GAP-102). Kozmos draws them all with this one part.

**The words, the tone and when it shows are the product's.** Kozmos decides
none of them: it draws what it is given, and a new state is new words and a
tone, not a new component.

It wears the **map controls' surface** (decision 40), from the same owned rule
as `MapControlButton`, so the two cannot drift:

- the **page's own surface**, opaque, with the Control corner (16) and **no
  border**, in the light theme and the dark (decision 47);
- the **map controls' elevation**, three shadows (`shadow-map-control`,
  `--semantics-elevation-map-control`), and the SDK's 32px backdrop blur;
- at least **48px tall**, with 8px above and below, 12px at the sides and 8px
  between the mark and the words;
- a **24px mark**, the size every map control's mark is drawn at. The SDK's box
  is 28; Kozmos's icon and spinner scales go from 24 to 32;
- the words **regular, 13px on a 16px line**, in `foreground/300` — the SDK's
  `#464A53` in the light theme. No brand font ships, so the system's sans draws
  them, as it draws the map controls'.

SwiftUI and Compose draw no blur: the surface is opaque, so a blur behind it
would not show, and the pill looks the same without one. SwiftUI casts the same
three shadows. Compose casts one 8dp elevation (`KozmosShadows.kt`), Material's
key and ambient light, where the web casts three: Compose here has no layered
shadow.

It is as wide as its words, up to a map control's longest (16rem), and then
wraps: longer words, or a longer language, make it taller rather than cut.

The colours are Kozmos's emotion roles for text and glyphs on the page
(`Semantics.Emotion.*.text`): the SDK's own green and red read 3.6:1 and 4.3:1
as words on white, under the 4.5:1 text needs.

`warning` fills the surface with a named token pair: `Emotion/alert/fill`, the
SDK's bright amber (`alert/600`, bright in both themes), under
`Emotion/alert/onFill`, the ink its words and mark are drawn in. The fill does
not turn over with the theme, so its ink stays black in both: 10.56:1 in the
light theme and 13.14:1 in the dark. React, SwiftUI and Compose all read the
pair.

## The product's mark

`icon` replaces the tone's own mark, and is drawn at 24px in the tone's
colour. `icon={null}` draws none. The mark is never announced: the words say
what is happening, which is also why the turning arc is decorative and not a
second status.

Both marks here come from `@kozmos-ds/icons`. Walking improves accuracy passes
`Walking`, the SDK's walking figure, which the progress tone draws in the
theme's blue as the SDK does. No Bluetooth passes `BluetoothOff`, the Pointr
Icon Library's outline. `bluetooth-off` is in the icon name list, so
`Icon name="bluetooth-off"` reaches it too, and SwiftUI's and Compose's
`KozmosIcon` draw it by that name.

<Canvas of={Stories.NoBluetooth} />

Two of the SDK's marks are not in `@kozmos-ds/icons`: neither Figma file Kozmos
reads for the SDK draws them, and icons come from Figma rather than being drawn
here. Until they are, these stories pass `icon={null}` and draw no mark, rather
than the tone's own triangle standing in for the SDK's:

- **Wayfinding Unavailable**: the SDK's walking figure, struck through, beside
  a pin;
- **Turn Back**: the SDK's U-turn arrow.

The `warning` tone keeps its own mark, the dark triangle, for a warning the
product has no mark of its own for; it is Turn Back that passes `icon={null}`
(SwiftUI's `showsIcon: false`, Compose's `icon = null`).

## Announcing

The pill is a live region. `live` takes Alert's and Notice's three values:

- **`polite`**, the default, for every tone: `role="status"`, read when the
  screen reader next pauses. None of these states is an emergency, and a status
  that interrupted would cut across the route instruction being read —
  `NavigationAnnouncer` reads those assertively, and the pill's states change
  often: calculating, established, calculating again.
- **`assertive`**: `role="alert"`, for a state that cannot wait.
- **`off`**: announces nothing, for words said somewhere else.

**Keep it rendered, and change its words.** A status that appears with its
words already in it is not read by every screen reader — NVDA reads a live
region's changes, not its arrival. With no words the pill draws nothing and
keeps its region, so its first words are read too:

```tsx
<MapStatusPill tone={status?.tone}>{status?.words}</MapStatusPill>
```

import type { ReactNode } from "react";
import { MapOverlay, MapStatusPill, type MapStatusPillProps } from "@kozmos-ds/react";
import { BluetoothOff, Walking } from "@kozmos-ds/icons";

type Positioning = "calculating" | "walking" | "established" | "noBluetooth";

// The product's words, in the visitor's language, and its tone for each.
const STATUS: Record<
  Positioning,
  { tone: MapStatusPillProps["tone"]; words: string; icon?: ReactNode }
> = {
  calculating: { tone: "progress", words: "Calculating Precise Position" },
  walking: { tone: "progress", words: "Walking improves accuracy", icon: <Walking /> },
  established: { tone: "success", words: "Established" },
  noBluetooth: { tone: "danger", words: "No Bluetooth", icon: <BluetoothOff /> },
};

// Rendered all the time, with no words while there is nothing to say, so
// its first words are read as well as every change after them.
export function PositioningStatus({ positioning }: { positioning?: Positioning }) {
  const status = positioning ? STATUS[positioning] : undefined;
  return (
    <MapOverlay position="bottom-center">
      <MapStatusPill icon={status?.icon} tone={status?.tone}>
        {status?.words}
      </MapStatusPill>
    </MapOverlay>
  );
}
