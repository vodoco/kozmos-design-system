# DatePicker

DatePicker retains the browser's native date input. External `aria-describedby`
IDs are merged with helper/error guidance; explicit error state cannot be hidden
by `aria-invalid={false}`. The decorative icon follows the module's text direction.

DatePicker uses the browser's date input; DateRangePicker composes start and end fields.
Provide field labels, constraints and validation feedback; browser-localized entry is distinct from the stored date string.

import Kozmos

// A Kozmos field around the system picker, which opens the system calendar:
// the label above it names the picker for VoiceOver, the helper is its hint,
// and the bounds are React's min and max. There is always a date.
struct VisitDate: View {
    @Binding var date: Date

    var body: some View {
        KozmosDatePicker(
            selection: $date,
            label: "Visit date",
            helperText: "Within the next 30 days",
            minimumDate: .now,
            maximumDate: .now.addingTimeInterval(30 * 24 * 60 * 60)
        )
    }
}
`}

import java.time.LocalDate

// A read-only field, labelled inside, that opens the system's date dialog.
// date is null until one is chosen.
@Composable
fun VisitDate(date: LocalDate?, onDateChange: (LocalDate) -> Unit) {
    KozmosDatePicker(date = date, onDateSelected = onDateChange, label = "Visit date")
}

## In Safari

`className` lands on the field. A utility class passed there styles it in Chrome, Edge,
Firefox and Safari 26.4, and is ignored in Safari 26.0 to 26.3, where the field keeps its
own look: those versions apply no `@scope` rule to an `<input>` (GAP-174), and Kozmos's
utilities are scoped. Use the props, the provider's `tokens`, an inline `style` or your
own CSS, and `wrapperClassName` for the layout around it. Guides › Platform support ›
Fields in Safari has the detail.
