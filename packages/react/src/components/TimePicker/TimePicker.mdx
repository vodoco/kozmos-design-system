# TimePicker

A time field: the browser's own, with its segmented typing in the reader's clock, and a button at
its end that opens a list of times (decision 104), Combobox's list as Figma's Open variant
(`444:11455`) draws it. The value is an `HH:MM` string, as `<input type="time">`'s is, through the
input's own `value`, `defaultValue` and `onChange`; a time chosen from the list is typed into the
field, so `onChange` and a form's change listeners hear it as typing.

External `aria-describedby` IDs merge with helper/error guidance, and an explicit component error
remains invalid. The owned field layout follows module direction and exposes a focus indicator for
native segments, including engines that do not match them with `:focus-visible`. The host owns any
time-zone or scheduling rules.

## The list of times

The button, and Alt+Down Arrow or F4 in the field, open the list under the field, as wide as it, on
the field's time; the list takes focus, and the arrows, Home and End move in it. A time chosen by
Enter, Space or the pointer is typed into the field; that or Escape closes the list and returns focus
to the button. It works in every engine: Chromium's own clock button gives way to Kozmos's, and
Safari and Firefox draw none, so for the first time they offer a list.

The times run from `min` to `max` (the input's own, `00:00` to `23:59` by default) every `step`
seconds, or every 30 minutes when `step` asks for less than a minute or nothing. They read in
`locale`'s own short time (`09:30`, `9:30 AM`), by default the document's language, and `hourCycle`
sets 12 or 24 hours; the typed field keeps the browser's clock. `chooseTimeLabel` names the button
and, with no `label`, the list (`"Choose time"` by default). `open` with `onOpenChange` controls it,
and `defaultOpen` opens it at first; Storybook's `Open` story draws it open. Disabled or read only,
the button cannot open it.

## The arrow keys

With a `step` of whole minutes (`300` for 5), Up and Down Arrow in the field step the time by it,
whichever part of the time is focused, on the step's grid from `min` and carrying into the hour:
`08:00` back is `07:55`, `08:03` on is `08:05`. They stop at `min` and `max` when the field has one,
and otherwise go round midnight (`23:55` on is `00:00`); an empty field starts at the first time going
on, at the last going back. Each step is typed into the field, so `onChange` hears it. With no `step`,
or one in seconds, the arrows are the browser's, which step the focused part by one. The typed time is
always drawn in the browser's own clock: `locale` and `hourCycle` set only the list's.

## Mixed

With several features selected, a time whose values differ is one field for all of them (GAP-255,
decision 188). `mixed` says the field stands for those values: it holds no time of its own, and
"Multiple values" (`mixedLabel`) is drawn where a text field draws its placeholder, in its colour.
A time field draws no placeholder, so the words lie over its empty segments, which give way to them,
and a screen reader hears them once, as the field's description; the drawn words are hidden from it.
In focus, the segments come back to be typed in. The list opens on no time. A typed or chosen time
is the edit, and the product clears `mixed`; `onResetMixed` draws "Reset to multiple values"
(`resetMixedLabel`) under the field once it is edited, never while it is disabled or read-only, and
hands focus back to the field. An uncontrolled field is emptied as it turns mixed, and on reset.

On SwiftUI the system's compact picker stays, as decision 104 says, under the mixed label, and
VoiceOver hears the field's name with "Multiple values" as its value. On Compose the field shows the
label and TalkBack says it as the field's state; Material 3's time dialog cannot show no time, so it
opens at 00:00, as it does for no time.

In Figma, Mixed is a value of the State axis, as on Input and Combobox, so a mixed field that is also
disabled, read only or in focus cannot be drawn. A Mixed variant has no Reset Mixed layer; Mixed Text
and Reset Mixed Text hold the words, for a board in another language.

import { useState } from "react";
import { TimePicker } from "@kozmos-ds/react";

// Each selected feature's opening time; where they differ, the field shows
// "Multiple values" and the list opens on no time.
export function OpeningTimeAcrossSelection({ opens }: { opens: string[] }) {
  const [edit, setEdit] = useState<string | undefined>(undefined);
  const differs = opens.some((time) => time !== opens[0]);
  return (
    <TimePicker
      label="Opens"
      value={edit ?? (differs ? "" : opens[0])}
      mixed={differs && edit === undefined}
      onChange={(event) => setEdit(event.target.value)}
      onResetMixed={differs ? () => setEdit(undefined) : undefined}
    />
  );
}

## In Safari

`className` lands on the field. A utility class passed there styles it in Chrome, Edge,
Firefox and Safari 26.4, and is ignored in Safari 26.0 to 26.3, where the field keeps its
own look: those versions apply no `@scope` rule to an `<input>` (GAP-174), and Kozmos's
utilities are scoped. Use the props, the provider's `tokens`, an inline `style` or your
own CSS, and `wrapperClassName` for the layout around it. Guides › Platform support ›
Fields in Safari has the detail.
