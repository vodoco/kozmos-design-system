# TimePicker

TimePicker retains native time-entry behavior. External `aria-describedby` IDs
merge with helper/error guidance, and an explicit component error remains invalid.
The owned field layout follows module direction and exposes a focus indicator for
native segments, including engines that do not match them with `:focus-visible`.

Uses the browser's time input with Kozmos field styling, labels and validation feedback.
The browser supplies the picker interaction; the host owns any time-zone or scheduling rules.

// The picker hides its label, which VoiceOver still says: KozmosFieldWrapper
// shows it above the field, as React's label is. There is always a time.
struct ArrivalTime: View {
    @Binding var time: Date

    var body: some View {
        KozmosFieldWrapper(label: "Arrival time") {
            KozmosTimePicker(selection: $time, label: "Arrival time")
        }
    }
}
`}
    kotlin={`
import androidx.compose.runtime.Composable
import com.kozmos.components.timepicker.KozmosTimePicker
import java.time.LocalTime

// A read-only field, labelled inside, that opens the system's time dialog.
// time is null until one is chosen. The field and the dialog keep the
// device's clock, 12- or 24-hour, and write the time in the locale's style.
@Composable
fun ArrivalTime(time: LocalTime?, onTimeChange: (LocalTime) -> Unit) {
    KozmosTimePicker(time = time, onTimeSelected = onTimeChange, label = "Arrival time")
}
`}

## In Safari

`className` lands on the field. A utility class passed there styles it in Chrome, Edge,
Firefox and Safari 26.4, and is ignored in Safari 26.0 to 26.3, where the field keeps its
own look: those versions apply no `@scope` rule to an `<input>` (GAP-174), and Kozmos's
utilities are scoped. Use the props, the provider's `tokens`, an inline `style` or your
own CSS, and `wrapperClassName` for the layout around it. Guides › Platform support ›
Fields in Safari has the detail.
