# OTPInput

A segmented numeric code field with configurable length, paste handling and field feedback.
Use its value callback to collect the code; verification and authentication belong to the host.

On every platform, the cells take a decimal digit from any script, such as the Arabic-Indic ٣, the
Devanagari ३ or the full-width ３, and hold the ASCII digit of the same value, so the code the host
receives (React's `onChange`, SwiftUI's `value` binding, Compose's `onValueChange`) and the cells
draw is always `0`–`9`, typed, pasted or passed as `value`. Anything else, such as a letter, `²` or
`½`, is dropped. Digits are read code point by code point, so a digit joined to a mark or a keycap
keeps its value ("1́" and "1️⃣" are 1) and the mark is dropped.

In React, a digit an IME composes, as a Japanese or Chinese IME composes a full-width one, is
entered once, when the composition ends. Two digits composed at once enter only the first, since a
cell's `maxLength` is 1. What reaches the cell while an IME composes, such as a paste or a new
`value`, gives way to the digit the composition commits. A digit two UTF-16 units long, such as the
Adlam 𞥑, can be pasted into React's cells but not typed: each cell's `maxLength` is 1. SwiftUI and
Compose take the whole code in one text field, so they have no per-cell limit.

In React, a digit typed into a filled cell replaces its digit and moves on, whether the cell was
clicked, reached with Tab, or given the focus as the digit before it was typed, so a full code can
be typed over from its first cell. A focused cell's digit is selected, so a touch keyboard's digit
replaces it too, and the same digit typed over itself still moves on.

## A code to start with

In React, an uncontrolled OTPInput starts with the code `defaultValue` gives it, read on mount
only: its digits are normalised to ASCII and cut to `length` as `value`'s are. `value` wins when
both are given. A code passed this way is not the user's: it calls no `onChange` and tracks no
`otp_code_completed`, and a full one the user then edits stays a full code. To start again from
it, give the field a new `key`. SwiftUI and Compose hold no code of their own: the code they start
with is the one the host's binding or state starts with.

## Read only and errors on native

On SwiftUI and Compose the field itself says it is read only and says its error (GAP-235, GAP-236): Compose
puts "Read only" in the field's state description (`readOnlyLabel`, for the product's own words) and the error
message as the field's `error`; SwiftUI says "Read only", then the error message, as the field's accessibility hint
(`readOnlyLabel` too). SwiftUI draws a read-only field read only, not disabled (decision 222): its value at full
strength and selectable, never dimmed, as React's and Compose's; so are its date and time pickers and ColorPicker.
OTPInput says its digit count first.

    KozmosOTPInput(
        value = code,
        onValueChange = onCodeChange,
        label = "Verification code"
    )
}
