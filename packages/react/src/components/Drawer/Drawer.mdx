# Drawer

Drawer presents contextual content from an edge of the viewport without
committing to a dashboard, map, or CMS-specific layout.

## Inline, under a fixed header

`placement="inline"` on `Drawer` draws the drawer in place, `absolute` against the nearest
positioned box, as Backdrop's `placement="inline"` does (GAP-198): a panel that sits in the region
under a fixed header instead of covering it, as Pointr Cloud's Get started panel does. Give the
region `position: relative`; the drawer takes no room in the flow, so it covers the region's content,
not the header.

- **It floats** (decisions 139 and 148). A right or left drawer sits 16 from every edge of the region
  it reaches. It is 420 wide, or the region less 16 on each side when that is narrower, and as tall
  as its content, up to the region less 16 at the top and the bottom, and then it scrolls. Its
  border goes all the way round, and its four corners are the container's. `side` is physical, as
  it is for a fixed drawer: right to left, pass `side="left"` for a panel at the inline end. A top
  or bottom drawer (BottomSheet's) stays at its edge, across the region, and stops at the region's
  far edge, so it can't grow over the header.
- **It scrolls with its region.** An inline drawer is `absolute`, so it moves with whatever scrolls
  the box it is positioned in. To keep it pinned under the header, keep the positioned region still,
  put the page's scroller inside the region, and render the Drawer outside that scroller.
- **It is a panel, not a dialog** while it isn't modal, the default: a labelled `complementary`
  landmark beside the page, not a `dialog`.
  - Nothing outside it is inert or hidden from readers, and the page keeps scrolling and taking
    presses.
  - It takes focus only when its `DrawerTrigger` opens it. A panel the product opens in code, such as
    Get started on a first visit, leaves focus where it is; to move focus in yourself, focus an
    element in `onOpenAutoFocus`.
  - Tab and Shift+Tab move in and out of it in the page's order. Focus is never held inside.
  - A press or focus outside it, on the header too, leaves it open. To close it then, close it in
    `onInteractOutside`. A press on its `DrawerTrigger` isn't outside: the trigger closes it itself.
  - Escape closes it only while focus is inside it, and `onEscapeKeyDown` can refuse that. Escape in
    the page is the page's: it reaches the page unprevented, so a Search clears and an
    AICompanionPanel closes. One thing it can't reach: Radix tells only its newest layer, so a
    Popover or menu opened before your code opens the panel doesn't hear Escape until the panel
    closes. One opened after it does.
  - A product's `onKeyDown` on it, or round it, sees every key, Tab too. No focus guards are added to
    the page.
  - Closing gives focus back only if it was inside: to the trigger, or with no trigger to what had
    it as the panel opened. Focus the user has put elsewhere stays where it is, and that includes
    the page's background.
  - Render a `DrawerTitle` in it, or pass `aria-label`: nothing else names it. It warns in
    development when nothing does. A `complementary` landmark belongs at the top level, so inside
    `main`, pass `role="region"`.
- **With `modal`**, it is a dialog again. Its scrim is drawn over the region alone, and the rest of
  the page is inert, as under any modal.

`placement="fixed"`, the default, is the drawer as it was: drawn in the theme's portal over the
window, and modal unless `modal={false}`. BottomSheet is a Drawer, so it takes `placement` too: an
inline sheet rises from the bottom of its region.

The close sits at the inline end and the header's room for it with it, so they mirror right to left,
whichever `side` the drawer is on. `closeLabel` names the close, "Close drawer" by default, as
Dialog's does.

<PlatformSnippets
  react={`
import { useState } from "react";
import {
  Button,
  Drawer,
  DrawerContent,
  DrawerDescription,
  DrawerFooter,
  DrawerHeader,
  DrawerTitle,
  DrawerTrigger,
  Input,
} from "@kozmos-ds/react";
export function Example({ onSave }: { onSave: (name: string) => void }) {
  const [open, setOpen] = useState(false);
  const [name, setName] = useState("Ground floor");
  return (
    <Drawer open={open} onOpenChange={setOpen}>
      <DrawerTrigger asChild>
        <Button>Manage layer</Button>
      </DrawerTrigger>
      <DrawerContent side="right">
        <DrawerHeader>
          <DrawerTitle>Manage layer</DrawerTitle>
          <DrawerDescription>Update the layer name.</DrawerDescription>
        </DrawerHeader>
        <Input
          label="Layer name"
          value={name}
          onChange={(event) => setName(event.target.value)}
        />
        <DrawerFooter>
          <Button variant="outline" onClick={() => setOpen(false)}>
            Cancel
          </Button>
          <Button
            onClick={() => {
              onSave(name);
              setOpen(false);
            }}
          >
            Save changes
          </Button>
        </DrawerFooter>
      </DrawerContent>
    </Drawer>
  );
}
  `}
  vue={`
<script setup>
import { KozmosDrawer } from "@kozmos-ds/vue/react-bridge"
// @kozmos-ds/vue wraps the Drawer root only: it has no DrawerTrigger, DrawerContent, DrawerHeader, DrawerTitle, DrawerDescription or DrawerFooter, so it cannot draw a drawer yet.
</script>

<template>
  <KozmosDrawer />
</template>
  `}
  swift={`
KozmosDrawer(
    isPresented: $isDrawerPresented,
    side: .right,
    title: "Manage layers",
    description: "Update map display settings.",
    bodyText: "Drawer body content"
)
  `}

KozmosDrawer(
    open = isDrawerOpen,

    side = KozmosDrawerSide.Right,
    title = "Manage layers",
    description = "Update map display settings.",
    bodyText = "Drawer body content"
) {
    ScreenContent()
}
  `}
