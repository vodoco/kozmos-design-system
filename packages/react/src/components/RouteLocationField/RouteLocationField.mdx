# Route Location Field

Controlled place search with a separate resolved-place identity, building/floor context, explicit clearing and a choose-on-map action.

<Canvas of={Stories.Search} />
<Canvas of={Stories.Resolved} />

`query` is editable text, never a location identity. `location.value` and suggestion values are stable host entity IDs. `onSelect` delivers the complete suggestion, including its secondary context. Blank or duplicate suggestion IDs are omitted rather than resolved arbitrarily. The host clears both identity and query in `onClear`.

`idle` and `ready` allow suggestions; `loading`, `empty` and `error` omit stale suggestions while keeping the query editable. Disabling the whole field also disables clearing and map selection. The default `filterMode="local"` uses case-insensitive substring filtering of label, ID and description.

For SDK/server-ranked results, choose `filterMode="host"` (`.host` on SwiftUI; `KozmosRouteLocationFilterMode.Host` on Compose). This preserves the supplied order and synonym/fuzzy/translated matches without filtering them again. Blank/duplicate IDs and non-ready states remain guarded in both modes. The host still owns request cancellation and rejecting stale responses.

<Canvas of={Stories.HostFiltered} />

Localize the field, placeholder, status/empty text and clear/map/open/close labels. Resolved names and context wrap; suggestion rows retain the existing compact Combobox presentation, with full names and context available to assistive technology.

Automatic selection analytics omit place IDs and query text. The host still receives the
resolved suggestion through the explicit selection callback and owns its data/consent policy.

The host owns requests, cancellation, focus restoration, keyboard/sheet insets and announcements. Ignore stale responses after selection, a newer query, clearing or leaving setup. Combobox may report a selected label through `onQueryChange` as well as calling `onSelect`; callback ordering is not a cross-platform contract. Drive requests from unresolved query state, not every callback without checking resolved identity.

## Text-action design preview

A resolved place shows a text action instead of a repeated close icon. Supply `onEdit` to show **Change** for a resolved place; without it, **Clear location** still calls `onClear` and does not pretend to edit. The host retains the original identity separately while rendering `location={null}` and a draft query. Supply `onCancelEdit` to restore that identity and focus; only `onSelect` commits a replacement. While editing, **Clear search** calls `onClear`; the host clears its draft and keeps the retained place, as the journey example does. Localize `changeLabel`, `cancelEditLabel` and `clearSearchLabel`. The controlled Navigation journey demonstrates this behavior and disables Continue during an unresolved edit.

React, SwiftUI and Compose expose `onEdit`/`changeLabel` and `onCancelEdit`/`cancelEditLabel`. Change is vertically centered beside the whole selected endpoint and its accessible name includes the field label, so From and To actions are distinguishable. Swift retains the original initializer (including trailing map callbacks); use its explicit `onEdit:` overload for editing, passing `nil` when only adding Cancel. Native unresolved clearing retains its existing `clearLabel`/`onClear` contract. Panel close controls are unchanged. Artwork/design and physical-device accessibility approval remain separate.

Native fields now compose Core Combobox's `KozmosPickerAction` commands rather than a separate SDK map button. Existing Swift initializers and Compose call sites remain source-compatible; the intentional interaction change is that map selection is available only inside the open unresolved picker. For a resolved endpoint, choose Change (or clear it) before opening the picker. Native `currentPosition` and `currentPositionLabel` are optional and follow the same host-validity rules below. Core supplies the command buttons, locked-state enforcement and close-before-callback behavior.

**Select from the map** lives inside the open dropdown below the suggestions, not beneath the selected card. Supply `currentPosition` only when the host has a usable resolved blue-dot fix; **Current position** appears above the map action and delivers that exact object through `onSelect`. Null, blank-ID and disabled positions are omitted. Localize `currentPositionLabel`; the host also localizes the selected position's label/context. These choices remain available during loading, errors or unmatched queries. They are separately typed action choices, not fabricated place IDs or search matches. On React, arrow keys navigate all rows, Enter activates, and Escape dismisses and returns focus to the input; native versions use accessible Core buttons. Selecting an action does not insert its label into the search query.

The component does not acquire permissions or decide fix freshness, accuracy, floor validity or routing suitability. The host must validate the fix again at selection/calculation, invalidate an unusable selected position, and decide whether it is a snapshot or follows live movement. Rendering a blue dot alone is not sufficient. The journey's **Blue dot available** story is deterministic fixture data, not real positioning. Current-position availability is opt-in per field; the example enables it for From only, with no automatic selection or changes to To.
