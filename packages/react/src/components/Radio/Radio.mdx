# Radio Group

A set of checkable buttons—known as radio buttons—where no more than one of the buttons can be checked at a time.

## Usage

Use radio buttons when:
- Users need to select a single option from a list.
- All available options should be visible at once (unlike Select).
- There are fewer than 5-7 options.

## Cards and tiles

`variant="card"` draws an option as a bordered box: an image or icon (`media`), the ring, the title (`label`) and a `description`. `variant="tile"` draws a smaller box of an icon over the title, for a grid of short choices, such as the transition editor's nine (GAP-158). Lay them out with a `Grid` inside the `RadioGroup`.

Each box is one radio, named by its title alone; its description is its description (`aria-describedby`), and its image or icon is decoration, hidden from assistive technology. The group keeps one Tab stop, and the arrow keys move and choose. The chosen box's edge turns theme 600 and a pixel heavier, and the card's ring shows its dot or the tile its check, so the choice is never told by colour alone. `description` also draws a line under a default radio's label.

**Arrows follow the order, not the grid.** As the WAI-ARIA radio group pattern has it, every arrow key moves to the next or the previous option in the order they are written, wrapping at the ends: in a three-column grid of tiles, Down moves to the next tile in the row, not to the one below it. Write the options in reading order.

**A box needs a title.** Its description is never its name: a card or tile with no `label` has no name, and in development Kozmos warns once in the console (SwiftUI logs it in a debug build; Compose logs it in a debuggable app). Give an icon-only tile a name of its own: `aria-label` on React, `.accessibilityLabel(_:)` on SwiftUI, `Modifier.semantics { contentDescription = … }` on Compose. On Compose an untitled card is still read by its description, as Compose has no separate name: give it a `label`.

**On SwiftUI** the description is read after the name as the element's custom content, at high importance, so VoiceOver speaks it whether or not the reader turned on Speak Hints; its key, "Description", is looked up in your app's `Localizable` strings. Compose reads it after the title, in the one node. A Compose card or tile fills the width it is given, so side by side in a `Row` give each `Modifier.weight(1f)`, as the snippet below does. `KozmosRadioGroupItem` is now generic over its media, `KozmosRadioGroupItem<Media>`: every initialiser compiles unchanged, but code that names the type needs a parameter, `KozmosRadioGroupItem<EmptyView>` for an option without media.

**On Vue** a bridged `KozmosRadioGroupItem` cannot reach a bridged `KozmosRadioGroup` (GAP-230), so a working group of cards or tiles cannot be drawn through the bridge yet.
