# `@kozmos-ds/react/dashboard`

Pointr Cloud's Dashboard modules (the register's `CLOUD-UI-*` rows; decision 88) ship from this entry, with a
stylesheet of their own, `@kozmos-ds/react/dashboard.css`, so an SDK or Core product never pays for them (decision
183, owner, 13 Nov 2026). The package's main entry and `style.css` hold none of their code, and checks fail if
either ever does. They are web parts: React now, Vue later (GAP-016), Figma, a Claude Design card and Storybook;
no SwiftUI or Compose.

```tsx
import "@kozmos-ds/react/style.css";
import "@kozmos-ds/react/dashboard.css";
import { BrandLoader } from "@kozmos-ds/react/dashboard";
```

## Adding a module

A module named `<Name>` (PascalCase, a name the main entry does not export) brings these, and nothing else needs
registering: the status report, the website, the Claude Design cards, the inventory and the bundle budget find it
from the folder.

| What                   | Where                                                                      | The rule                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The component          | `packages/react/src/dashboard/<Name>/<Name>.tsx`, and `index.ts` beside it | `export * from "./<Name>";` in its `index.ts`, and one line, `export * from "./<Name>";`, appended to [`index.ts`](index.ts). Nothing outside this folder imports from it (`entry.test.ts`).                                                                                                                                                                                                                                                            |
| Core parts             | imported from the package's source, as any part does                       | `import { Backdrop } from "../../components/Backdrop/Backdrop";`. The build turns each import that leaves this folder into an import of `@kozmos-ds/react`, so no Core part is copied into the entry and a part's React context is one. So such an import must name what the main entry exports, by that name: `cn`, the recipes' internals and the like are not exported, and the build stops (`vite.dashboard.config.mts`). Join classes with `clsx`. |
| Its types              | in the module                                                              | Its props are its own, declared in the module. They are rolled into `dist/dashboard/index.d.ts`; a Core props type a module re-declares in its public props is copied there, so prefer its own interface.                                                                                                                                                                                                                                               |
| Its CSS                | `packages/styles/src/dashboard/<kebab-name>.css`                           | Owned rules only, inside `@kozmos-owned { … }`, classes `kozmos-<kebab-name>-*`, tokens only, logical sides, and the reduced-motion rule for any loop (both the media query and `[data-kozmos-motion="reduced"]`). One `@import "./dashboard/<kebab-name>.css";` line appended to `packages/styles/src/dashboard.css`. No utility classes in the module: this folder is not scanned for `style.css`'s utilities, so one only it writes draws nothing.   |

## How it is built

`vite.config.mts` builds the main entry; `vite.dashboard.config.mts` then builds this one into the same `dist`:
`kozmos-react-dashboard.mjs` (over one file per module in `dist/esm/dashboard`), `kozmos-react-dashboard.cjs`, and
the types in `dist/dashboard/index.d.ts`, `.d.mts` and `.d.cts`. `dashboard/package.json` at the package's root
resolves the entry for Node 10's resolution. `@kozmos-ds/styles` builds `dashboard.css`
(`vite.dashboard.config.mts` there, through `postcss/dashboard-sheet.cjs`), and React ships it byte for byte.
