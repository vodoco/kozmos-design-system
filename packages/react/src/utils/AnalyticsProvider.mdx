# AnalyticsProvider

Kozmos parts report what people do with them, such as a switch being toggled or a result being opened.
A provider collects those events and hands them to your `onDispatch` in batches, for you to send where
you like. In React it is `AnalyticsProvider`; in SwiftUI, the `.kozmosAnalytics(batchDelayMs:onDispatch:)`
modifier; in Compose, `KozmosAnalyticsProvider(onDispatch, batchDelayMs)`; in Vue, `KozmosAnalyticsProvider`
from `@kozmos-ds/vue`, with `@dispatch`.

## Batches

- A batch opens with an event and is delivered `batchDelayMs` after it, 2000 by default, with every event
  sent meanwhile, in the order they were sent. A later event does not move the delivery, so a steady
  stream arrives every `batchDelayMs`, not when it stops.
- What is still waiting when the provider goes away is delivered then: when `AnalyticsProvider` unmounts,
  when the view with `.kozmosAnalytics` leaves the hierarchy, and when `KozmosAnalyticsProvider` leaves the
  composition. None delivers early when the page is hidden or the app moves to the background.
- A provider takes the events of the parts inside it. A nested provider takes its own subtree's, and the
  one above it gets none of them.
- An event carries `component`, `eventName`, `properties` and `timestamp`: milliseconds since 1970 in
  React and Compose, seconds in SwiftUI.
- SwiftUI and Compose call `onDispatch` on the main thread. A SwiftUI product can add its own events to the
  batches through `@EnvironmentObject var analytics: KozmosAnalytics` and its `trackEvent`; a Compose
  product, by calling the tracker in `LocalKozmosAnalytics.current` inside the provider.

With no provider, React drops the events and warns once in a development build, and SwiftUI prints each
one. A SwiftUI tracker set with `.environment(\.kozmosAnalytics) { event in … }` gets each event as it
happens, unbatched.

## Compose

`KozmosAnalyticsProvider` batches as React's and SwiftUI's do. Its event's `properties` are strings, where
React's and SwiftUI's take any value. With no provider, Compose prints each event; a tracker provided
through `LocalKozmosAnalytics` itself gets each event as it happens, unbatched.

## Vue

`KozmosAnalyticsProvider` batches as React's does, and `useKozmosAnalytics()` gives a product's own
`trackEvent`, as React's hook does. It needs no React: `KozmosButton` reports its `button_clicked` to it.
Every part `@kozmos-ds/vue/react-bridge` draws inside it reports to it too: the bridge gives each a React
`AnalyticsProvider` that hands its events on (GAP-230), so they reach the batch a moment after a native
part's event of the same moment. With no provider, an event goes nowhere.

    react={`
import type { ReactNode } from "react";
import { AnalyticsProvider } from "@kozmos-ds/react";

declare function send(events: readonly unknown[]): void;

export function App({ children }: { children: ReactNode }) {
  // Interaction events arrive in batches, every 2000ms by default.
  return (
    <AnalyticsProvider onDispatch={(events) => send(events)}>
      {children}
    </AnalyticsProvider>
  );
}
    `}
    vue={`
<script setup>
import { KozmosAnalyticsProvider } from "@kozmos-ds/vue"

// Interaction events arrive in batches, every 2000ms by default: those of
// the Vue parts inside and of the parts the React bridge draws inside.
const props = defineProps({ send: Function })
</script>

<template>
  <KozmosAnalyticsProvider @dispatch="(events) => props.send(events)">
    <slot />
  </KozmosAnalyticsProvider>
</template>
    `}
    swift={`
import SwiftUI
import Kozmos

// The events of the parts inside arrive in batches, each 2000ms after its
// first event by default, and what is left when this view leaves the
// hierarchy. onDispatch is called on the main thread.
struct TrackedApp<Content: View>: View {
    let send: ([KozmosAnalyticsEvent]) -> Void
    @ViewBuilder let content: Content

    var body: some View {
        content.kozmosAnalytics(onDispatch: send)
    }
}
    `}
    kotlin={`
import androidx.compose.runtime.Composable
import com.kozmos.providers.KozmosAnalyticsEvent
import com.kozmos.providers.KozmosAnalyticsProvider

// The events of the parts inside arrive in batches, each 2000ms after its
// first event by default, and what is left when this leaves the
// composition. onDispatch is called on the main thread.
@Composable
fun TrackedApp(send: (List<KozmosAnalyticsEvent>) -> Unit, content: @Composable () -> Unit) {
    KozmosAnalyticsProvider(onDispatch = send) {
        content()
    }
}
    `}
