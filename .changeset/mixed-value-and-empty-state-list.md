A mixed value on Input, NumberInput, Select and Combobox, and a list in EmptyState (GAP-153, GAP-165; decision 132).

- **A field can stand for several values at once (GAP-153)**, as a property of a multi-selection whose features differ. `mixed` shows none of the field's own value and "Multiple values" (`mixedLabel`) in its place, as the placeholder, which a screen reader says once with the empty field (Select's trigger, a button, is described with it instead, its drawn words kept from screen readers). It is controlled, as the selection is the product's: the visitor's first edit comes through the field's own change callback (`onChange`, `onValueChange`), and the product clears `mixed`, so the field keeps its mixed state until it is edited. `onResetMixed`, given for a field whose values differ, draws "Reset to multiple values" (`resetMixedLabel`) under the field once it is no longer mixed, never while it is disabled or read-only; pressed, focus returns to the field and the product drops the edit and sets `mixed` again. An uncontrolled Input or NumberInput drops its default value while mixed, is emptied as it turns mixed, and is emptied on reset.
  - Input, NumberInput and Combobox take the four props. A mixed Combobox checks no option and shows no choice, though the visitor may still type a query; a choice is the edit, the clear button empties only the query (it reports no empty choice), and the reset empties the text with the choice. A mixed NumberInput's steppers are disabled: a step would write one number over every feature's own; typing edits it.
  - Select takes them on its root, which holds the value: mixed, it gives Radix no value, so `SelectValue` shows the mixed label and no option is checked, and `SelectTrigger` is described with it and draws the reset, never while the Select is disabled at its root or its trigger. A Select given `mixed` always gives Radix a value, so it never switches between controlled and uncontrolled: without your `value` it holds the choice, from `defaultValue` only while it is not mixed, and never shows a value it held before it turned mixed. `SelectProps` is exported, and `SelectTrigger` now always carries an `id` (yours, or one of its own) so focus can return to it.
  - `FieldWrapper` takes `mixed`, `mixedLabel`, `mixedId`, `onResetMixed` and `resetMixedLabel`, which the fields use; `MixedValueProps` is the four a field takes.
- **EmptyState takes `list` (GAP-165):** items drawn as a bulleted list under the description, from its leading edge in the 280 column, above any progress and the action, and read in order as a list of so many items; `listLabel` names it. Each item is a line of text or the product's own inline content, such as a Link. An empty list draws nothing.

`@kozmos-ds/styles` gains `.kozmos-field-reset`, the reset's text button, and `.kozmos-empty-state-list`. SwiftUI and Compose take the same: `mixed`, `mixedLabel`, `onResetMixed` and `resetMixedLabel` on their Input, NumberInput and Combobox, on Compose's `KozmosSelectTrigger`, and on SwiftUI's `KozmosSelect`, which gains `KozmosSelectField`, the closed field it draws from `KozmosSelect(value:placeholder:label:…)`; `list` and `listLabel` on EmptyState. The Figma importer paints State=Mixed (NumberInput's steppers disabled there), a Reset Mixed boolean (a Mixed variant has no reset layer) and Mixed Text and Reset Mixed Text on the Input, NumberInput, Combobox and Select sets, and a List boolean with List Item 1–3 Text on EmptyState; Code Connect maps them on all three platforms. Vue's bridge takes `mixed` as a boolean and `@reset-mixed`; a mixed Select cannot be drawn from Vue yet, as its trigger is not bridged (GAP-230).
