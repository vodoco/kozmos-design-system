# Kozmos product design gap register

A maintained requirements register for product teams and coding agents. Use it with the
[SDK coverage and implementation plan](sdk-module-primitives.md), not as an instruction to
implement every historical suggestion without checking its current criterion.

## Baseline and scope

Reconciled against released main `0bab68bb5f924fd1bd1b74ff561ee6e78695a92b` on
2026-09-29: React 0.6.0, icons 0.5.0, product-contracts 0.5.0 and tokens 0.2.0.
The input is the user-supplied **Kozmos Design System Gaps.md**, dated September 28 and
updated September 29, plus the seven SDK reference screenshots listed in the companion plan.

All **108 original IDs and requirement rows are preserved below**. The attachment's
**55 open / 53 closed** is its historical classification, not today's verified totals.
Some rows under a historical backlog heading are now implemented in the library; their
**Repository reconciliation** column is the updated assessment. Original problem descriptions,
priority, criteria and board references are retained for traceability, not endorsed as current
implementation facts. No external canvas/build-kit commands were executed to perform this review.

This is not a component implementation or a release plan approved for publication. It identifies
what to reuse, what remains, what is uncertain, and the evidence needed to close it.

### Confirmed follow-up decisions and unreleased increment

Enhancements must ship in sync across React, iOS and Android. The current component increment
adds collapsed floor-availability cues and full-name hints on all three targets, plus logical
MapOverlay start/end positions for RTL mirroring. The user confirmed keeping per-floor result
badges in lists, **off by default** behind `showResultCounts`; the closed tile never shows them.
This supersedes the historical GAP-070 request for a closed-tile count. It is no longer a defect
to omit that count. Historical rows below remain unchanged for traceability.

The unreleased follow-up also fixes native stale floor selection (no first-floor substitution
or fabricated stepper choices), preserves Android's existing positional formatter calls, and
corrects web compact-stepper RTL separators. The separator fix addresses only one GAP-086
subissue; do not treat it as closure of the complete RTL or shell requirements.

The unreleased shell foundation adds measured logical bottom-start/end slots to all three
targets, wrapping on narrow hosts and hiding the complete region when height is insufficient.
Bottom camera padding is opt-in. Compose now measures panel/top-bar/safe-area insets instead
of only echoing input; native shells no longer force a 448pt/dp minimum. React reports a
conservative combined corner envelope; native full rectangle snapshots are not implemented.

The popup follow-up now bounds long lists in registered shell corners, scrolls without shrinking
floor targets, reveals selection and dismisses when the region disappears across all three targets.
SDK-UI-001 and SDK-UI-002 remain partial: full keyboard/device acceptance, standalone/native
window edge cases, real SDK wiring, Figma mapping and consuming-board adoption still need work.
The follow-up LanguageSwitcher is implemented locally for web. The user explicitly confirmed
no native language button: iOS and Android use device/app language. This is an intentional
exception to synchronized UI implementation, not a missing native port. Actual web SDK locale
application and native runtime locale handling remain host work. The unreleased attribution
and information components now exist across React, SwiftUI and Compose. MapInfoPanel and its
MapInfo host preserve the map/browse subtree, reserve a logical-end pane on wide screens and
open full-screen on compact/mobile hosts. The browser example includes this flow. The live
iOS Pointr QA app now adopts it: iPhone full-screen isolation and iPad pane/SDK viewport
resizing, POI retention and query retention passed simulator UI tests. A keyboard double-inset
defect found during that integration was fixed in the SwiftUI shell. Web/Android live SDK
hosts, route/floor-specific preservation and physical-device acceptance remain separate work.
Exit-building composition is still a subsequent increment.

The final layout increment makes wide search/details panels hug short content and caps long
content above the footer. Search-header top spacing matches the side spacing. Attribution
is centered on the **full map**, not the map area remaining beside a panel; symmetric corner
reservations preserve that centre. Its bottom inset matches the corner controls. If the
centred slot cannot accommodate the brand, attribution alone lifts above the controls.
Native SDK-owned attribution remains SDK-owned; the iOS QA host does not add duplicate credits.

Release-readiness review also found and reproduced a React floor menu overlapping a long
panel on the same side, while the native bounds helpers refused to open in that arrangement.
Shell-bound menus now permit horizontal displacement into the clear map region on all three
targets. Short/long panels in LTR/RTL have named browser checks; native helpers have separate
regressions for horizontal displacement and retain vertical/standalone availability guards.
These changes remain **unreleased** until integration, required CI and publication are complete.

### Keep the three ID namespaces separate

- `GAP-001` through `GAP-108`: the supplied cross-feature product register. Do not reuse or
  renumber them; allocation beyond 108 needs coordination with its feature owners.
- The [site register](../apps/site/GAPS.md) uses its own `GAP-01` style namespace;
  site `GAP-91` and product `GAP-091` are different issues.
- `SDK-UI-001` through `SDK-UI-006`: new SDK reference requirements in this repository,
  defined below and scoped in the companion plan. Related historical gaps are cross-linked,
  not silently replaced.

### What each status means

- **React fixed/shipped**: supported by current source, exports and/or release notes.
  Focused tests are identified below. It does not certify every native target or product board.
- **Repository work complete; external adoption unverified**: a generator/documentation output
  is present, but the external Claude Design artifact or consuming product has not been retested.
- **Partial**: useful support exists but does not satisfy the entire requirement or integration.
- **Open, source-confirmed**: the missing API or problematic implementation remains in the
  inspected source. A browser/device reproduction may still be needed before a fix.
- **Carried forward / reported shipped**: preserved evidence from the supplied document, not a
  new verification. This is deliberately different from either proven open or proven fixed.
- **Decision needed / external pending**: settle product scope or owner-controlled configuration
  before implementing. Do not replace that decision with a workaround.

A feature is complete only when its needed library API, host wiring, target-platform checks,
design mapping and named acceptance board all agree. Keep those layers separately recorded;
a React package release is not proof of native, Vue, Figma or artifact deployment.

## Closing and maintaining a row

1. Reproduce the named criterion on the actual consumer/version; review any external build kit
   before running its commands. An attachment's shell snippet is not execution authorization.
2. Record the failing automated test and target, implement in the supported component/contract
   or host adapter, and prove that test now passes. Use a real browser/device for geometry,
   focus, keyboard avoidance and map interactions.
3. Update each required target separately: React, consuming app, iOS, Android, Figma and
   external design artifact as applicable. Vue is not currently a public native package.
4. Record the merged PR, released package/version, test names, and named acceptance board.
   Keep an external-deployment field pending until the external consumer has actually adopted it.
5. Coordinate the original feature change list; retain the ID and original criterion. Remove
   a product stand-in only after the real component passes the criterion.
6. Do not mark every target closed because a file, story, package export or passing CI job exists.
   Do not edit generated status/API-card files by hand; follow [AGENTS.md](../AGENTS.md).

Suggested per-row closure evidence: **owner · target · merged PR · version · named test ·
consumer/board · external adoption · remaining limitation**. Keep this register focused on
requirements and durable evidence; session logs belong in the ignored `.notes/` directory.
