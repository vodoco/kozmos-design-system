## 1. Rules in force

These are standing instructions from Olcay, not preferences:

1. **Never edit `packages/` from the site's work.** Another session owns the
   components. Where the system falls short the site **records a gap** in
   `GAPS.md` and works around it in its own code — never in `packages/`,
   because a workaround upstream destroys the evidence.
2. **The one rule.** Every visible part of the site is a Kozmos component and
   every colour, radius, shadow, size and spacing value is a Kozmos token.
   `apps/site/scripts/check-ds-only.mjs` enforces the mechanical half.

   `git add -A` or a whole directory.
4. **Olcay merges.** Do not merge a pull request, do not enable auto-merge.
5. **Audit before "done".** An adversarial self-audit is expected, and a
   green test proves nothing until it has been run against the unfixed code.

### 2.1 Twelve CI failures that could not happen on a Mac

`main`'s first CI run of the site failed twelve checks that pass locally.
Root cause: **nothing loads a brand font.** `--semantics-typography-family-brand`
names Readex Pro and no `@font-face`, webfont link or font file exists in the
repository — the tokens' own `$description` says so. Everything therefore
renders in `--semantics-typography-family-system`, which ends at the host's
`system-ui`: SF Pro on macOS, a much wider DejaVu Sans on the Linux the CI
runs. The same page wraps in different places on the two.

Reproduced locally by forcing Verdana, which matched CI to the decimal
(754.4px, 779.4px, 6.169 screens). Two real defects behind it:

- The home page's claim takes one line in SF Pro and two in a wide sans. The
  ring was `min(26rem, 100%, 52svh)`, which left **7px** under the buttons at
  1280×720 — so the second line put them 34px below the fold, and 11px below
  at 1366×768. Now `44svh`: 23px spare at the tightest. Above about 945px
  tall the 26rem cap binds and nothing changes.
- A part's name is one unbreakable identifier (`SelectScrollDownButton`) at
  24px in a 288px column. In the wider font it ran three component pages
  sideways at 320px — WCAG 1.4.10. `.site-part-name` lets it break.

Both checks now run **twice**, the second time in `WIDE_SANS`
(`Verdana, 'DejaVu Sans', sans-serif` — the wide font macOS has, then the one
Linux has). Reverting the ring fails only the two new hero checks; reverting
the class fails the component pages' 320px check. A sweep of all 138 linked
pages at 320px in the wide font found no other offender. Filed as **GAP-90**.

The home page's height budget went from "six screens" to "six and a half",
with the reason written into the test: 5.9 screens here and 6.1 there are the
same page in two fonts.

### 2.2 Eleven assets addressed from the domain's root

examples and demos. At base `/` they resolve; under `/kozmos-design-system/`
they ask `vodoco.github.io` for files that are not there. They now go through

the pattern and names any it finds — it listed all eight in the demos the

component page, foundations and the roadmap loaded with no failed request, no

### 2.4 A tripwire that could not trip

**GAP-37** ("`SearchBar` shows the browser's clear button beside its own") was
fixed upstream in `d89e405` at 10:53 today. The site's test did not notice,
and could never have: it read
`getComputedStyle(field, "::-webkit-search-cancel-button")`, and a `-webkit-`
shadow pseudo-element answers with the **host element's** own values —
measured, `display`, `appearance` and `width` all came back as the input's
348px box. It could only ever report the button as drawn.

It now reads the promise where it is made, in the owned rule, out of the
document's stylesheets; deleting that rule from the CSSOM makes it report the
button drawn again.

**GAP-50** ("Spinner, Skeleton and the loading Button ignore reduced motion")
was fixed on 2026-09-23 in `550b561` and had **no test at all**, so it sat
unnoticed for four days. It has one now that reads each animation with the
preference and without it, so it cannot pass on an animation that was never
there.

Both were found by reading the upstream commits, not by a test. That is the
more useful finding, and it is written into `apps/site/README.md` under
"A tripwire must be able to trip".

## 7. Traps met today

- **The host picks the font.** Nothing ships a brand font, so a layout
  measured on one machine is not the layout another gets. Measure anything
  that depends on where text wraps in a wide sans as well.
- **A `-webkit-` shadow pseudo-element cannot be read.**
  `getComputedStyle(el, "::-webkit-search-cancel-button")` returns the host's
  values. When a promise lives in CSS a browser will not hand back, read the
  rule out of `document.styleSheets`.
- **A root-absolute asset is invisible in development.** It resolves at `/`
  and 404s under a project path. The only way to see it is to build with
  `BASE_PATH` and serve the artifact under its subpath.
- **`pgrep -f` inside a loop matches its own command line**, so
  `until ! pgrep -f "playwright/test/cli"; do …; done` never exits.
- **lint-staged commits the whole index.** `git commit <paths>` with an
  unrelated staged deletion swept it into the wrong commit; the deletion had
  to be taken back out with `git checkout <commit>^ -- <path>` and an amend.
- **`gh pr edit` fails silently here** (a Projects-classic error leaves the
  body unchanged). PATCH through `gh api` and read the body back.
- **A React Router prerender with a basename** writes the pages into a folder
  named after the prefix and leaves the assets at the build's root. The Pages
  workflow merges the two; it reads the folder name out of `BASE_PATH` rather
  than spelling it twice.
