## 1. What Is Code Connect

Code Connect is a bridge between a codebase and Figma's Dev Mode. It connects components in code repositories directly to components in Figma design files. When implemented, Figma's Dev Mode displays true-to-production code snippets from an actual design system instead of autogenerated code examples.

Key value propositions:

- Developers see real, maintained code samples when inspecting components in Dev Mode
- Reduces context switching between Figma, Storybook, and code repositories
- Creates a shared source of truth for both design and engineering teams
- Enhances the Figma MCP (Model Context Protocol) server's ability to guide AI agents with precise implementation details
- Drives consistent adoption of design system components

Code Connect does NOT generate code from designs. It maps existing production code to design components so developers see the correct imports, props, and usage patterns.

## 2. Architecture & How It Works

### Conceptual Flow

```
Design System (Figma)          Code Repository
  [Components]                   [Components]
  [Variants]          <-->       [Props/APIs]
  [Properties]                   [.figma.tsx files]
  [Design Tokens]                [figma.config.json]
       |                              |
       v                              v
  Figma Dev Mode  <--- publish ---  CLI
       |
       v
  Developer sees production code snippets
```

### Data Flow

1. Developer creates `.figma.tsx` (or `.figma.ts`, `.figma.swift`, `.figma.kt`) files in the codebase
2. Each file calls `figma.connect()` linking a code component to a Figma node URL
3. Property mappings translate Figma properties (variants, booleans, strings, instances) to code props
4. An `example` function returns the code snippet that will be displayed in Dev Mode
5. Running `figma connect publish` sends these mappings to Figma's servers
6. When a developer inspects a component in Dev Mode, they see the mapped code snippet with dynamic property values

### Critical Constraint

Code Connect files are NOT executed as code. They are parsed as strings. This means:

- Logical operators (ternaries, conditionals) output verbatim, not evaluated
- Dynamic `figma.connect()` construction via loops is impossible
- The `example` function is a template, not runtime code

## 4. Two Implementation Approaches

### Code Connect UI

- Runs entirely inside Figma's browser interface
- Language-agnostic (works with any framework)
- Direct GitHub repository integration (optional)
- Manual component mapping for non-GitHub repos
- AI-generated code previews
- Custom notes and usage instructions per mapping
- Built-in component playground for real-time testing
- Quick to set up, ideal for simple visual linking

### Code Connect CLI

- Runs locally within the repository
- Supports property mappings and dynamic code examples
- Deeper integration accuracy
- Publishes connections via terminal commands
- Supports Storybook integration
- Custom parsers and Template API
- Full programmatic control

**Important**: Only one connection type can be used per component, but UI and CLI can coexist in the same project for different components.

## 6. Installation & Setup

### React / HTML (npm)

```bash
npm install --global @figma/code-connect@latest
```

Or as a dev dependency:

```bash
npm install --save-dev @figma/code-connect
```

### SwiftUI (Swift Package Manager)

Add to `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/figma/code-connect", from: "1.0.0")
]
```

Add to target dependencies:

```swift
.target(name: "YourTarget", dependencies: [
    .product(name: "CodeConnect", package: "code-connect")
])
```

### Jetpack Compose (Gradle)

In `build.gradle.kts`:

```kotlin
plugins {
    id("com.figma.code.connect") version "1.+"
}

dependencies {
    implementation("com.figma.code.connect:code-connect-lib:1.+")
}
```

### Authentication

Option A - Environment variable:

```bash
export FIGMA_ACCESS_TOKEN=your_token_here
```

Option B - CLI flag:

```bash
npx figma connect --token=your_token_here
```

Token requirements:

- "Code Connect" scope: Write
- "File content" scope: Read

### Interactive Setup (React only)

```bash
npx figma connect --token=TOKEN
```

Walks through:

1. Directory selection (e.g., `./src/ui`)
2. Figma file URL input
3. `figma.config.json` creation
4. Prop mapping (automatic or AI-powered, React only)
5. Component matching via terminal interface
6. Output directory for `.figma.tsx` files
7. Review and file creation

**Note**: HTML/Web Components cannot use interactive setup; mappings must be created manually.

## 7. Configuration File (figma.config.json)

Located at the project root (alongside `package.json`, `.xcodeproj`, or `build.gradle.kts`).

### Common Options (All Platforms)

```json
{
  "codeConnect": {
    "include": ["src/components/**/*.figma.tsx"],
    "exclude": ["src/components/internal/**"],
    "parser": "react",
    "label": "React",
    "language": "typescript",
    "interactiveSetupFigmaFileUrl": "https://www.figma.com/design/FILE_KEY/...",
    "documentUrlSubstitutions": {
      "https://old-file-url": "https://new-file-url"
    }
  }
}
```

| Key                            | Description                                                         |
| ------------------------------ | ------------------------------------------------------------------- |
| `include`                      | Glob patterns for files to parse                                    |
| `exclude`                      | Glob patterns for files to skip                                     |
| `parser`                       | Override auto-detection: `react`, `html`, `swift`, `compose`        |
| `label`                        | Label shown in Figma Dev Mode (defaults to framework name)          |
| `language`                     | Syntax highlighting: `typescript`, `swift`, `kotlin`, `html`, `raw` |
| `interactiveSetupFigmaFileUrl` | Pre-set Figma file URL for interactive setup                        |
| `documentUrlSubstitutions`     | Map old URLs to new when files are duplicated/moved                 |

### React-Specific Options

```json
{
  "codeConnect": {
    "parser": "react",
    "importPaths": {
      "src/components/*": "@my-ds/components"
    },
    "paths": {
      "@components/*": ["src/components/*"]
    },
    "imports": ["import { Button } from '@my-ds/components'"]
  }
}
```

| Key           | Description                                                  |
| ------------- | ------------------------------------------------------------ |
| `importPaths` | Remap relative imports to package names (wildcard supported) |
| `paths`       | Mirror `tsconfig.json` paths for TypeScript alias resolution |
| `imports`     | Manually override generated import statements                |

### SwiftUI-Specific Options

```json
{
  "codeConnect": {
    "parser": "swift",
    "xcodeprojPath": "path/to/Project.xcodeproj",
    "swiftPackagePath": "path/to/Package.swift",
    "sourcePackagesPath": "path/to/SourcePackages",
    "importMapping": {
      "PackageName": "ImportName"
    }
  }
}
```

| Key                  | Description                                         |
| -------------------- | --------------------------------------------------- |
| `xcodeprojPath`      | Path to `.xcodeproj` file                           |
| `swiftPackagePath`   | Alternative: path to `Package.swift`                |
| `sourcePackagesPath` | Source Packages directory (defaults to DerivedData) |
| `importMapping`      | Map package paths to import names                   |

## 9. Code Connect File Format

### React (.figma.tsx)

```tsx
import React from "react";
import { Button } from "../ui/Button";
import figma from "@figma/code-connect";

figma.connect(
  Button, // Code component
  "https://www.figma.com/design/FILE?node-id=65%3A5", // Figma node URL
  {
    props: {
      label: figma.string("Label"),
      disabled: figma.boolean("Disabled"),
      variant: figma.enum("Variant", {
        Primary: "primary",
        Secondary: "secondary",
        Danger: "danger",
      }),
      icon: figma.instance("Icon"),
    },
    example: (props) => (
      <Button
        variant={props.variant}
        disabled={props.disabled}
        icon={props.icon}
      >
        {props.label}
      </Button>
    ),
  },
);
```

### SwiftUI (.figma.swift)

```swift
import CodeConnect

struct Button_connection: FigmaConnect {
    let component = Button.self
    let figmaNodeUrl = "https://www.figma.com/design/FILE?node-id=65%3A5"

    @FigmaString("Label") var label: String
    @FigmaBoolean("Disabled") var disabled: Bool
    @FigmaEnum("Variant", mapping: [
        "Primary": .primary,
        "Secondary": .secondary,
        "Danger": .danger
    ]) var variant: ButtonVariant

    @FigmaInstance("Icon") var icon: Icon

    var body: some View {
        Button(label, variant: variant, disabled: disabled) {
            icon
        }
    }
}
```

### Jetpack Compose (.figma.kt)

```kotlin
import com.figma.code.connect.*

@FigmaConnect("https://www.figma.com/design/FILE?node-id=65%3A5")
class ButtonConnection {
    @FigmaProperty(FigmaType.Text, "Label")
    val label: String = ""

    @FigmaProperty(FigmaType.Boolean, "Disabled")
    val disabled: Boolean = false

    @FigmaProperty(FigmaType.Enum, "Variant")
    val variant: ButtonVariant = Figma.mapping(
        "Primary" to ButtonVariant.Primary,
        "Secondary" to ButtonVariant.Secondary,
        "Danger" to ButtonVariant.Danger
    )

    @FigmaProperty(FigmaType.Instance, "Icon")
    val icon: @Composable () -> Unit = {}

    fun example() {
        Button(
            label = label,
            variant = variant,
            disabled = disabled,
            icon = icon
        )
    }
}
```

## 10. Property Mapping API (React)

Import: `import figma from "@figma/code-connect"`

### figma.string(propertyName)

Maps a Figma text property to a string prop.

```tsx
props: {
  label: figma.string("Label");
}
```

### figma.boolean(propertyName, mapping?)

Maps a Figma boolean property. Normalizes Figma variants like "Yes"/"No", "True"/"False", "On"/"Off" to actual booleans.

```tsx
// Simple boolean pass-through
props: {
  disabled: figma.boolean("Disabled");
}

// Boolean with value mapping (conditional rendering)
props: {
  icon: figma.boolean("Has Icon", {
    true: <Icon />,
    false: undefined, // omits the prop when false
  });
}
```

### figma.enum(propertyName, mapping)

Maps a Figma variant/enum property. Keys must match exact Figma variant option names. Values are NOT normalized (unlike booleans).

```tsx
props: {
  size: figma.enum("Size", {
    "Small": "sm",
    "Medium": "md",
    "Large": "lg",
  }),
  // Enum to component mapping
  icon: figma.enum("Icon Type", {
    "Heart": <HeartIcon />,
    "Star": <StarIcon />,
    "None": undefined,
  })
}
```

### figma.instance(propertyName)

Maps a Figma instance-swap property to a JSX component. The nested component must have its own `figma.connect()` definition for the snippet to resolve.

```tsx
props: {
  icon: figma.instance("Icon"),
  avatar: figma.instance("Avatar")
}
// In example: <Button icon={props.icon} />
```

Type variants:

- Default: Returns JSX element
- `figma.instance<string>("PropName")`: Returns the component name as a string

### figma.children(layerNames)

Maps unnamed child instances by their layer name in Figma (not a Figma property name).

```tsx
props: {
  tabs: figma.children("Tab"),                    // single named layer
  items: figma.children(["Tab 1", "Tab 2"]),      // specific layers
  icons: figma.children("Icon*"),                  // wildcard matching
  allChildren: figma.children("*"),                // all children
}
```

### figma.nestedProps(layerName, mapping)

Access properties of a child instance without creating a separate `figma.connect()` for it. Takes the layer name (not prop name) as first param.

```tsx
props: {
  buttonProps: figma.nestedProps("Button Shape", {
    size: figma.enum("Size", {
      Small: "sm",
      Large: "lg",
    }),
    label: figma.string("Label"),
  });
}
// In example: <Button size={props.buttonProps.size}>{props.buttonProps.label}</Button>
```

### figma.textContent(layerName)

Extracts and renders the actual text content from a named text layer in the design.

```tsx
props: {
  heading: figma.textContent("Heading Layer"),
  body: figma.textContent("Body Text"),
}
```

### figma.className(values)

Concatenates string values into a className, filtering out undefined/empty results.

```tsx
props: {
  className: figma.className([
    "btn-base",
    figma.enum("Size", { Small: "btn-sm", Large: "btn-lg" }),
    figma.boolean("Rounded", { true: "btn-rounded", false: undefined }),
  ]);
}
```

### Advanced: getProps and render

- `getProps<T>()`: Access child component props from a parent component
- `render<T>(props => ...)`: Conditionally render based on resolved props

## 13. Property Mapping API (HTML / Web Components / Angular / Vue)

Import: `import figma, { html } from "@figma/code-connect/html"`

All React mapping functions are available with identical signatures:

- `figma.string()`
- `figma.boolean()`
- `figma.enum()`
- `figma.instance()`
- `figma.children()`
- `figma.nestedProps()`
- `figma.textContent()`
- `figma.className()`

Template uses tagged `html` template literal:

```typescript
example: (props) => html`

`;
```

Key differences:

- No component reference as first argument (just URL and config)
- Boolean attributes render contextually (omitted when false)
- JavaScript must be in `<script>` tags within templates
- Literal `${}` in Lit elements must be escaped: `\${value}`
- Framework auto-detection via `package.json` (Angular, Vue, Web Components)

## 14. Variant Mapping

Variant mapping allows connecting different code components to different variants of the same Figma component.

### React Example

```tsx
// Primary variant
figma.connect(PrimaryButton, "https://figma.com/design/FILE?node-id=X", {
  variant: { Type: "Primary" },
  example: () => <PrimaryButton />,
});

// Danger + Disabled combination
figma.connect(DangerButton, "https://figma.com/design/FILE?node-id=X", {
  variant: { Type: "Danger", Disabled: true },
  example: () => <DangerButton disabled />,
});
```

### How Variant Selection Works

1. Each `figma.connect()` call can include a `variant` object
2. When a developer selects a variant in Figma, Code Connect finds the matching connection
3. Multiple variant conditions can be combined (AND logic)
4. The most specific match wins
5. If no variant match exists, the default (no variant restriction) connection is shown

### Mapping Figma Enums to Code Booleans

A Figma variant with "Yes"/"No" options can be mapped as:

```tsx
// Using figma.enum
figma.enum("Boolean Variant", { Yes: true, No: false });

// Using figma.boolean (auto-normalizes Yes/No, True/False, On/Off)
figma.boolean("Boolean Variant", { true: <Icon />, false: null });
```

## 15. Multi-Platform Design System Strategy

### The Challenge

A design team maintains a single Figma library with components (Button, Card, etc.) implemented across multiple platforms (React web, React Native mobile, SwiftUI iOS, Jetpack Compose Android), all sharing one Figma component.

### Solution: Custom Labels

Code Connect supports **custom labels** to distinguish platform implementations for the same Figma component:

```bash
# Publish React web components (default label)
npx figma connect publish --token=TOKEN

# Publish React Native with custom label
npx figma connect publish --label "React Native" --token=TOKEN

# Publish SwiftUI
swift package figma-connect publish --label "SwiftUI"

# Publish Jetpack Compose
./gradlew figmaConnectPublish --label "Compose"
```

Or in `figma.config.json`:

```json
{
  "codeConnect": {
    "label": "React Native"
  }
}
```

### Multi-Platform Project Structure

```
design-system/
  figma.config.json           (root config)
  packages/
    react-web/
      figma.config.json       (parser: react, label: React)
      src/
        Button/
          Button.tsx
          Button.figma.tsx
    react-native/
      figma.config.json       (parser: react, label: React Native)
      src/
        Button/
          Button.tsx
          Button.figma.tsx
    ios/
      figma.config.json       (parser: swift, label: SwiftUI)
      Sources/
        Button/
          Button.swift
          Button.figma.swift
    android/
      build.gradle.kts        (compose plugin + label config)
      src/
        Button/
          Button.kt
          ButtonConnection.figma.kt
```

### Key Principle

One Figma component node URL can have multiple Code Connect definitions across different platforms. In Dev Mode, developers see a dropdown/tab to switch between platform implementations (React, React Native, SwiftUI, Compose).

## 16. Tokens & Variables: Figma Variables vs Design Tokens vs Style Dictionary

### Figma Variables (Native)

Figma variables are the built-in token system within Figma. Types supported:

- **Number**: Spacing, sizing, border radius, opacity
- **Color**: Fill, stroke, effects
- **String**: Labels, configuration values
- **Boolean**: True/false logic

Features:

- Multiple modes (e.g., light/dark, compact/comfortable)
- Scoping (restrict where variables can be used)
- Code syntax mapping (for better handoff)
- Alias/reference variables (linking variables for theme switching)
- REST API for programmatic access (`GET /v1/files/:file_key/variables`)

### Design Tokens (W3C Standard)

Design tokens are platform-agnostic representations of design decisions following the W3C Design Tokens specification. They exist outside any specific tool.

### Style Dictionary

Style Dictionary is the most popular tool for transforming design tokens into platform-specific code. It generates:

- CSS custom properties
- SCSS variables
- iOS Swift constants
- Android XML resources
- Kotlin constants
- JavaScript/TypeScript constants

### How They Work Together

```
Figma Variables  --->  Export (REST API / Plugin)  --->  Design Tokens (JSON)
                                                              |
                                                              v
                                                        Style Dictionary
                                                              |
                                        +---------------------+--------------------+
                                        |                     |                    |
                                        v                     v                    v
                                   CSS Variables         Swift Constants      Kotlin Values
                                   (theme.css)          (Tokens.swift)       (Tokens.kt)
```

### Relationship to Code Connect

Code Connect and Style Dictionary / design tokens serve **different purposes**:

| Aspect        | Code Connect                          | Style Dictionary                     |
| ------------- | ------------------------------------- | ------------------------------------ |
| **Purpose**   | Maps component usage patterns         | Maps design token values             |
| **Scope**     | Components (Button, Card, etc.)       | Tokens (colors, spacing, typography) |
| **Output**    | Code snippets in Figma Dev Mode       | Platform-specific token files        |
| **When Used** | Design handoff (developer inspecting) | Build time (CI/CD pipeline)          |

**They are complementary**: Style Dictionary handles the token/variable layer, while Code Connect handles the component layer. A mature design system uses both.

### Figma SDS Reference Implementation

The Figma Simple Design System (SDS) demonstrates both:

- `npm run script:tokens:rest` generates `src/theme.css` from Figma Variables via REST API
- `.figma.tsx` files connect components to Figma via Code Connect
- `documentUrlSubstitutions` in config enables portable connections

### Tokens Studio for Figma (Plugin)

For teams needing more control, Tokens Studio provides:

- No-code interface for creating/managing tokens
- Connects tokens to Figma styles and variables
- Syncs to external code repositories (GitHub, GitLab, etc.)
- Works with Style Dictionary for transformation

## 17. CI/CD Integration

### GitHub Actions Workflow

```yaml
name: Publish Code Connect

on:
  push:
    paths:
      - "src/components/**/*.figma.tsx"
    branches:
      - main

jobs:
  code-connect:
    name: Code Connect Publish
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "18"

      - name: Install dependencies
        run: npm ci

      - name: Publish Code Connect
        run: npx figma connect publish --exit-on-unreadable-files
        env:
          FIGMA_ACCESS_TOKEN: ${{ secrets.FIGMA_ACCESS_TOKEN }}
```

### Key CI/CD Considerations

1. **Trigger on relevant files only**: Use `paths` filter to only run when `.figma.tsx` files change
2. **Use `--exit-on-unreadable-files`**: Ensures CI fails if any Code Connect file has errors
3. **Store token as secret**: Use `FIGMA_ACCESS_TOKEN` as a GitHub repository secret
4. **Run on merge to main**: Publish only after PR is merged, not on every push
5. **Minimize impact**: Only run on PRs relevant to Code Connect to avoid slowing other workflows

### Multi-Platform CI/CD

For multi-platform projects, set up separate jobs:

```yaml
jobs:
  publish-react:
    runs-on: ubuntu-latest
    steps:
      - run: npx figma connect publish --label "React"

  publish-react-native:
    runs-on: ubuntu-latest
    steps:
      - run: npx figma connect publish --label "React Native"

  publish-swiftui:
    runs-on: macos-latest
    steps:
      - run: swift package figma-connect publish --label "SwiftUI"

  publish-compose:
    runs-on: ubuntu-latest
    steps:
      - run: ./gradlew figmaConnectPublish
```

## 18. Figma MCP Server & AI Integration

Code Connect enhances the Figma MCP (Model Context Protocol) server, which is a bridge between AI agents and Figma design files.

### How It Works

1. Code Connect mappings are published to Figma
2. The Figma MCP server reads these mappings
3. AI agents (the coding agent, Copilot, etc.) query the MCP server
4. The server returns actual production code patterns instead of generic guesses
5. AI generates more accurate, design-system-compliant code

### Benefits for AI-Assisted Development

- AI agents get direct references to actual code, not generic component libraries
- Generated code uses correct imports, prop names, and patterns
- Reduces AI hallucination about component APIs
- Creates a feedback loop: better Code Connect mappings lead to better AI output

## 19. Best Practices

### Getting Started

1. **Start small**: Begin with simple, high-impact components (Button, Toggle, Input) to understand the mapping process before tackling complex ones
2. **Cross-functional collaboration**: Designers and developers should work together on property mappings
3. **Review in Dev Mode**: Always verify output in Dev Mode with both designers and developers

### Implementation

4. **One component at a time**: Map one component fully (all variants, all props) before moving to the next
5. **Use documentUrlSubstitutions**: Keep Code Connect files portable across duplicated Figma files
6. **Match Figma property names exactly**: Enum keys in `figma.enum()` must match the exact Figma variant option strings
7. **Organize Code Connect files alongside components**: Place `.figma.tsx` next to the component file it maps
8. **Use the interactive setup for React**: Leverage AI-powered prop matching to scaffold files quickly

### Multi-Platform

9. **Use custom labels**: Distinguish platform implementations with `--label` flag or config
10. **One Figma library, multiple Code Connect configs**: Maintain a single source of truth in Figma, with separate configs per platform
11. **Align property mapping across platforms**: Use consistent naming even if the syntax differs (Swift vs TypeScript vs Kotlin)

### Maintenance

12. **Automate publishing with CI/CD**: Set up GitHub Actions to publish on merge to main
13. **Surface best practices contextually**: Use Code Connect to tie documentation and usage guidelines to components
14. **Keep snippets focused**: Show the most common usage pattern, not every possible combination
15. **Version control Code Connect files**: They should be in the same repo as the components they map

### What NOT to Do

16. **Do not rely on Code Connect as documentation**: It supplements, not replaces, comprehensive design system docs covering principles, guidelines, accessibility, and version history
17. **Do not map internal/private components**: Only map components that are part of the public design system API
18. **Do not use dynamic logic in example functions**: Remember, these are parsed as strings, not executed

## 20. Limitations & Constraints

### Plan & Access

- Organization or Enterprise plan required (not available on Free, Professional, or Education plans)
- Full Design seat or Dev Mode seat required per user
- Personal access token with specific scopes needed

### Technical Limitations

- **Files are not executed**: The `example` function is treated as a string template, not runtime code. Ternaries and conditionals output verbatim.
- **No dynamic figma.connect()**: Cannot construct connections via loops or runtime logic
- **Manual property mapping**: Mapping properties to components is a manual, labor-intensive process. Files can become messy and may require refactoring.
- **One connection type per component**: Cannot use both UI and CLI approaches for the same component
- **HTML interactive setup not supported**: Web Components, Angular, and Vue mappings must be created manually
- **No auto-detection of platform context**: Code Connect cannot automatically detect whether a design is for mobile or web

### Framework Limitations

- Angular, Vue, and Web Components share the `html` parser, which may not perfectly represent framework-specific syntax
- Storybook integration is available but requires additional configuration
- Custom parsers are possible but require significant effort

### Operational

- When running `figma connect publish`, Figma collects: component paths, repository URLs, properties and code in `.figma` files
- Logging captures when components are published/unpublished and calls to get Figma data
- No offline mode: Publishing requires internet connection to Figma servers

## 21. Reference Implementation: Figma SDS

The **Simple Design System (SDS)** is Figma's official reference implementation demonstrating how Variables, Styles, Components, and Code Connect work together with a React codebase.

GitHub: https://github.com/figma/sds

### Project Structure

```
src/
  ui/
    primitives/       # Base components aligned with Figma components
    compositions/     # Practical responsive arrangements
    layout/          # React-only (no Figma counterpart): flexbox, containers
    icons/           # Auto-generated SVG components from Figma
    hooks/           # Custom React hooks
    providers/       # Context providers
    utils/           # Utilities
  figma/             # Code Connect files
  stories/           # Storybook stories
  theme.css          # Generated from Figma Variables
```

### Key Patterns

1. **Token generation**: `npm run script:tokens:rest` extracts Figma Variables via REST API and generates `theme.css`
2. **Icon generation**: `npm run script:icons:rest` auto-generates React icon components from Figma
3. **Portable URLs**: Uses `documentUrlSubstitutions` for file-agnostic connections: `"<FIGMA_INPUTS_CHECKBOX_GROUP>"` maps to actual Figma URLs
4. **Storybook integration**: Components have both `.figma.tsx` and `.stories.tsx` files

### Commands

| Command                      | Description                              |
| ---------------------------- | ---------------------------------------- |
| `npm run app:dev`            | Local dev server (localhost:8000)        |
| `npm run storybook`          | Storybook (localhost:6006)               |
| `npm run script:tokens:rest` | Generate CSS tokens from Figma Variables |
| `npm run script:icons:rest`  | Generate icon components from Figma      |
