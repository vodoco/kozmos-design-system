# Platform support and validation

Kozmos has one public component catalogue. Its live examples render React.
Implementation tabs document platform-specific code; they do not imply equivalent
APIs, complete coverage, passing tests, or production readiness.

## React

The live catalogue exercises `@kozmos-ds/react`. Release readiness also requires
package-install checks, supported-browser testing, accessibility review, and real
product integration. A passing story does not certify every state or consumer.

All 82 React implementation recipes are complete exported components: their
imports, state and required callback props are included. Follow the package README
for stylesheet and provider setup. Product-owned callbacks (such as routing and
persistence) must still be supplied by your application.

`pnpm docs:snippets:compile` extracts the exact displayed text, packs the local
publishable packages, installs them into isolated consumer projects, and compiles
the recipes with React 18 and 19. It uses strict TypeScript/NodeNext with library
checking enabled, without source aliases or injected application variables. The
same check runs inside `pnpm packages:install:check` in CI. Compilation does not
execute the recipe or prove accessibility, visual fidelity, or product behaviour.

### Fields in Safari

Safari 26.0 to 26.3, on macOS and iOS (and so every iOS browser and web view on those
versions), applies no `@scope` rule to an `<input>` or a `<textarea>` (GAP-174). Apple
fixed it in Safari 26.4; 17.4 to 18 were not affected, as MDN's compatibility data
records. Measured in Playwright's WebKit 26.0: every text-like `<input>` (text, search,
email, password, number, date, time, colour, range) and every `<textarea>` misses, while
a `<div>`, a `<button>` and a `<select>` take the same rule. Kozmos's utility classes are
emitted inside `@scope`, so on those versions none of them reaches a field. Every Kozmos
field draws from its own unscoped CSS instead, and draws there as in Chrome and Firefox:
`pnpm test:field-styles` measures every part with a field in all three engines.

- A utility class passed to a field's `className` (`px-4`, `w-72`, `border-destructive`)
  applies in Chrome, Edge, Firefox and Safari 26.4, and is ignored in Safari 26.0 to 26.3,
  where the field keeps its own look. Kozmos cannot change this: the scoping is what those
  versions mishandle.
- What reaches a field there: its props (`status`, `error`, `disabled`, and density from
  `ThemeProvider`), the provider's `tokens`, an inline `style`, and your own CSS loaded after
  Kozmos's. One class of yours overrides a field's base look (`.kozmos-input`,
  `.kozmos-textarea`); a part's own rules come after it, and some are two classes (Search's
  room for its icon, ColorPicker's for its swatch), which your selector must match.
- Around a field, use `wrapperClassName`: it lands on a `<div>`, which takes scoped rules.
- `<button>`, `<select>`, checkboxes and radios take scoped rules on those versions too.

## Vue — internal only

`@kozmos-ds/vue` is private and is not published to npm. Its adapters mount a React
root inside each Vue wrapper. Consumers therefore need React and React DOM as
well as Vue. These wrappers do not support server rendering.

Vue snippets are internal reference examples, not instructions to install a
released native Vue library. Only three component groups currently have stories;
that is test coverage, not the total number of exported wrappers. Nested context,
slots, events, two-way binding and teardown require separate adapter testing.

Maintainers can run `pnpm --filter @kozmos-ds/docs storybook:vue` to open the internal
Vue harness on port 6007. It is intentionally absent from the public sidebar.

## Swift and Kotlin — native references

The native packages have separate implementations and build pipelines. Their
snippets are not executed by this web catalogue. Some existing examples are
implementation excerpts, not complete applications. Check the actual package API
and native build/test results before using them. Native package delivery is
separate from npm publication.

## What is checked today

`pnpm docs:snippets:check` checks Kozmos-prefixed identifiers against each
platform's source tree. It does **not** compile examples, validate all imports or
props, or establish behavioural equivalence. Native builds and adapter tests do
not automatically compile the strings displayed in these documentation tabs.
`pnpm docs:snippets:vue:check` holds every name a Vue tab imports from
`@kozmos-ds/vue`, and every `Kozmos*` tag it draws, to what the harness exports,
and fails a tab that imports from any module but `@kozmos-ds/vue` and `vue`;
it does not run the tab.

Missing example text means **not documented**, not automatically unsupported.
Vue, Swift and Kotlin still have no equivalent compiler gate for their Docs text.
Their reference examples must not be described as validated recipes.
